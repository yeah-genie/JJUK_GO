# 보행 부담 중심 데모: 사용자 요청·데이터·구현

2026-10-31 KST, `codex/reference-ui-prototype`. 사용자 후속 요청: 확인 가능한 신호 자료를 우선 활용하고 사용자 입장에서 고칠 것. 이어서 신호 상세 X로 창을 없애고, 기존 Vercel 비교 화면처럼 우회하더라도 걷기 불편한 길을 줄이되 더 읽기 쉽게 만들 것. 새 자료는 공공데이터를 조사하고 기존 GitHub 자료부터 재사용할 것.

## 방향

**더 걷는 시간과 줄어드는 부담을 함께 보여준다.** 처음부터 긴 표를 읽히지 않고 계단·급경사·오르는 높이 세 지표를 먼저 보게 한다. 전체 비교는 ‘자세히’로 펼친다. 대안이 없으면 없는 경로의 열을 만들지 않는다. 휠체어가 통행 가능한 완만한 경사로와 부담스러운 급경사를 구별한다. ‘경사로 전부 회피’는 목표가 아니다.

배리어프리 지향은 현장 통행 보장과 다르다. 계단은 일반 보행자에게 부담, 일부 이용자에게 통행 불가 조건이 될 수 있다. 계단·경사만 줄여도 턱·좁은 길·단절된 입구가 남으면 통행이 막힐 수 있다. 과거 문서 [보행 확장 데이터와 개인 속도](../보행%20확장%20데이터와%20개인%20속도.md)와 현재 사용자 요청을 함께 반영했다.

## 무엇이 보행을 불편하게 하는가

| 항목 | 사용자에게 생기는 문제 | 데이터 판단과 적용 |
| --- | --- | --- |
| 계단·높은 턱 | 발을 들거나 바퀴를 들어야 함. 조건에 따라 통과 불가 | 현재 OSM 계단 태그는 제외 조건으로 사용. 턱 높이·턱 낮춤의 연속성은 아직 별도 미확인 |
| 종단 급경사·긴 오르막·내리막 | 힘·제동·균형 부담. 긴 완만한 오르막도 개인에 따라 부담 | 현재 지면 높이와 보행 간선의 경사 요약을 재사용. 8% 이상 거리와 누적 상승을 분리. 내리막의 무릎 부담·횡경사는 새 검증 필요 |
| 보도 폭·볼라드·주차·적치물 | 유모차·휠체어가 통과 못 하거나 차도로 내려가야 함 | 전역 최신 통과 폭·일시 장애물 자료는 확보하지 못함. 미확인을 ‘통과 가능’으로 계산하지 않음 |
| 울퉁불퉁한 노면·미끄럼·파손 | 진동·넘어짐·피로 | 도로 선만으로 판단 불가. 현장 측정/제보/갱신 시각 필요 |
| 횡단 거리·신호 | 오래 서 있거나 내 속도에서 건너기 부담스러움 | 기존 횡단 위치·길이·신호 이력 사용. 현재 상태와 과거 기록을 구별 |
| 실제 출입구·엘리베이터 연결/고장 | 목적지 앞에 가도 들어갈 수 없거나 되돌아가야 함 | 시설 점의 위치와 통행 가능한 연결·층·운영 상태를 별도 검증해야 함 |
| 쉬지 못하는 긴 구간·폭염·한파·혼잡 | 체력·날씨·군중에 따른 부담 | 휴식·환경은 후속 확장. 이번에는 계단·경사·횡단이라는 이미 계산 가능한 축부터 완성 |

근거는 서울연구원의 [대중교통시설 교통약자 접근성 지표 연구](https://www.si.re.kr/sites/default/files/2019-PR-40.pdf), 지자체의 [유니버설디자인 지침](https://www.goe.go.kr/resource/old/BBSMSTR_000000000200/BBS_202404030422465440.pdf), 서울시의 [이동약자 지도 설명](https://news.seoul.go.kr/traffic/archives/512992?listPage=1)이다. 이 자료에서 문제 유형을 추린 것이며, 쭉고 사용자 인터뷰의 빈도 순위나 개별 건강 상태의 판단은 아니다. 경사 비교 기준 8%를 법정 경사로 기준이나 개인의 통과 가능 기준으로 사용하지 않는다.

## 이번 구현

1. **X 닫기:** 네이버 정보창이 클릭 전파를 막아 외부 UI 핸들러만으로 닫히지 않던 것을, 실제 정보창의 X에 직접 연결했다. 클릭 전파를 차단하고 선택 상태도 지워 다음 갱신에 재등장하지 않게 한다.
2. **확인 가능한 신호 정보:** 30MB의 시간대 원본을 매번 전부 받는 대신, 기존 자료에서 충분한 표본과 적합도를 가진 기간의 지속시간만 1.27MB로 추출했다. 1,729 제어기 ID의 기록이며 검증된 현재 신호 1,729곳이라는 뜻이 아니다. `ref/day0/xd` 위상 앵커는 내보내지 않는다. 다른 시간의 기록을 현재 예상 위상 계산에 대입하지 않는다. 날짜·시각과 ‘과거 초록 약 N초’를 표시하고 색/시계 아이콘으로 구별한다. 현재 추정 게이트는 유지한다.
3. **길 선택:** 실제 유효 대안이 있을 때만 편한 길/빠른 길 선택을 보여주고 기존 원시 지표의 장점·추가 시간을 사용한다. 대안이 없는 경로는 꾸며내지 않는다.
4. **급경사 선호:** ‘급경사 덜 걷기’를 기본 ON으로 연결했다. 기존 우회 시간·겹침·개선/악화 허용 기준을 통과하고 노드 높이가 확인되는 후보들 중 급경사 거리→오르는 높이→시간 순으로 선택한다. OFF면 기존 최소 추가시간 순서다. 계단 제외는 기존 조건을 사용한다. 지형 미확인/육교·지하도는 0경사로 새로 승격하지 않는다. 급경사 완전 차단이나 휠체어 통행 보장은 아니다.
5. **읽기 순서:** 지도 비율과 하단 걷기 시작을 유지한다. 계획 상태의 불필요한 ‘다음 횡단’ 큰 행을 계단/급경사/오르는 높이로 바꾸고 상세 비교는 위로 펼친다. 걷기 시작 후에는 다음 횡단 안내가 돌아온다. 없는 대안의 열은 생략한다.
6. **초기 사용자:** 출발지 선택을 GPS 연결 완료로 오해하지 않게 바꿨고, 측정 전 큰 숫자를 ‘자동 맞춤’으로 바꿨다. 임시 속도는 작은 설명으로 둔다. ‘예상 보행·신호 대기 별도’를 명시한다. 출발·도착 검색 제목도 구분한다.

## 확인과 남은 일

신호 기록 화면, X 클릭 후 상세 제거, 초기 자동 맞춤, 보행 부담 펼침은 실제 브라우저에서 확인했다. 길음역→동덕여대 검증 설정(4.8km/h·추가3분)에서 편한 길28분/급경사220m/상승39m/신호횡단3곳과 빠른 길27분/320m/43m/6곳을 확인하고 선택 시 경로와 수치가 함께 바뀌는 것을 확인했다. 검증 후 자동 맞춤·추가0.5분을 복원했다. 추가 Node 검사에는 X 직접 닫기, 과거 기록의 현재 위상 차단, 다른 시간 출처, 급경사 선호가 기존 탈락 조건을 통과한 후보만 고르는지, 경로 선택 표시 조건을 포함한다. 단계별 캡처는 `usability-2026-10-31/`에 둔다.

야외 보행/실제 턱·노면·출입구 및 승강기 연결·개인 학습 정확도는 검증 전이다. 새 공공 API를 실행에 연결했다고 쓰지 않는다. 운영 사이트 배포와 기본 브랜치 병합은 하지 않는다.
