# 쭉고 Product Design 점검 — 2026-11-01

상태: 구현·로컬 자산 브라우저 검증 완료, 최종 배포 확인 준비. 운영 화면을 캡처한 뒤 로컬 UI 수정본을 같은 브라우저에서 검토했다. 390×844와 공유 화면 360×640, 별도 Playwright 브라우저 사용을 사용자에게 명시적으로 승인받았다. 실제 사용자 내장 탭을 변경하지 않았다.

## 범위와 근거

1. 홈: `01-home-before.png` → `01-home-after.png`. 장소 입력·내 위치·설정·최근 목적지.
2. 검색: `02-search-before.png` → `02-search-after.png`. 기본 검색/실제 카카오 응답, 빈 화면과 선택.
3. 경로 비교: `03-result-before.png` → `03-result-after.png`. 실제 성신여대입구역→성지관, 두 경로와 조건/상세.
4. 설정: `04-settings-before.png` → `04-settings-after.png`. 조건 변경과 복귀.
5. 걷기: `05-walking-before.png` → `05-walking-after.png`. 위치 권한 거부, 재연결, 회복. 이후 시험용 GPS로 약 16m를 이동시켜 종료 흐름 확인. 수정본은 '위치 연결 필요', 불필요한 오류 토스트 0개, 미검증 큰 말풍선 0개 확인.
6. 요약: `06-summary-before-simulated.png` → `06-summary-after-simulated.png`. **브라우저가 주입한 시험 GPS 기록**이며 실제 현장 이동이 아니다. 이후 캡처는 이 기록을 재생해 동일 조건으로 비교했다. 기기 GPS 정확도 검증을 대신하지 않는다.
7. 공유 카드: `09-share-asphalt-simulated.png`, `10-share-compact-simulated.png`, `11-share-visual-example.png`. 마지막 파일은 `sample=1`의 명시적 시각 예시(실제 GPS 아님). 기본/투명 PNG 다운로드, 알파 채널, 사진 선택/제거를 확인했다.

모든 위 스크린샷은 이번 실행에서 저장 후 직접 열어 확인했다. 처음 검색 '로딩 중' 캡처는 폐기하고 안정된 결과로 덮어썼다. 비교 그림은 동일한 단계·뷰포트의 전후 파일로 만든다.

로컬 8771 서버는 실행됐지만 Playwright에서 연결 거부/시간 초과가 났다. 수정 후 검토는 공개 운영 페이지의 엔진/지도/API를 유지하고 `ui.js`, `ui.css`, 마지막 확인에서는 `naver-map.js`도 작업 파일로 응답하는 로컬 자산 오버라이드 방식이다. 이 상태의 캡처를 운영 적용 확인이라고 말하지 않는다.

## 사용자 추가 요구

- 첫 페이지와 설정 개선. 출발/도착 입력을 한 덩어리로 묶고 브랜드 워드마크·직접 내 위치 연결을 배치했다.
- 예전 아스팔트색 `#242A32` 배경의 다크 선택. 기본 밝은 화면 유지, 설정에서 아스팔트 선택/기기 저장. 지도 제공자의 지도색은 임의 변경하지 않는다.
- 중간 진행을 캡처로 공유, 작업용 Preview 링크 요청. 운영 전 작업 브랜치 배포를 준비한다.
- 걷기 종료 후 NRC처럼 경로 실루엣과 거리·시간·페이스를 저장. 공유 화면·아스팔트/밝게/투명/사진 배경을 구현 중이며 실제 GPS 조각을 임의 연결하지 않는다.

## 최종 기능 확인

- 검색 버튼과 Enter 모두 실제 Kakao Maps 응답을 받음. '성신여대성지관' 기본 정확한 결과를 보존하고 외부 결과를 추가함(정확한 기본 결과가 사라지던 회귀 수정).
- 조건 출발 시각 4개가 실제 DOM 높이 44px로 보임. '이 조건으로 길찾기'로 돌아감. 자세한 계산/개인정보 설정은 일반 설정에 남겨 조건 화면의 하단 겹침을 없앰.
- 실제 네이버 지도에서 출발·도착 원 크기 28×28px 확인. 계획 중 자동 말풍선 0개. 신뢰를 잃은 안내 말풍선도 확대하지 않게 방어함.
- 설정에서 아스팔트 선택→홈 복귀로 색/선택 상태 저장 확인. `07-settings-asphalt.png`, `08-home-asphalt.png`.
- 공유 카드 실제 다운로드 이벤트 성공. 990×1800 PNG, 아스팔트는 모서리 alpha 255, 투명은 모서리 alpha 0 및 전체 범위 0~255 확인. 시험용 1px PNG 파일 선택과 사진 지우기 확인. 사진/좌표는 별도 서버로 업로드하지 않음.
- 아주 짧은 실측 기록의 평균 페이스는 보류(100m/60초 미만). 두 GPS 조각을 두 선으로 그리는 Node 검사 통과. 궤적 없는 기록은 계획 경로라고 표시.
- 360×640 공유 화면에서 배경 선택·사진·저장 버튼 모두 화면 안. 카드 미리보기는 축소되며 내보내기 해상도는 유지됨.
- Node 8종(reference UI, walk, profile, app shell, places, events, live 및 JS syntax) 통과. 실제 Redis/캐시는 환경 미설치로 SKIP. Python/수집·신호 엔진은 이번 변경 없음.
- 수정본 브라우저 실행 오류 0개. 네이버 지도 SDK의 기존 경고는 있었음. 네이티브 모바일 앱/야외 GPS 검증과는 구분함.

사용자 진행 공유 요청에 따라 실제 캡처와 작업용 Preview(98e80ab)를 중간에 전달했다. 최종 배포 식별자는 후속 확인으로 기록한다.

## 참고 서비스

이번 브라우저 실행에서 그늘로 공식 홈, 네이버/카카오 모바일 웹을 열고 `reference-*.png`를 저장·검토했다. 새 탭 기본 크기는 1280×720이므로 이 파일들은 모바일 앱 UI의 1:1 비교 근거가 아니다. 그늘로는 공식 홈의 앱 소개 화면/설명, 네이버는 검색창+지도, 카카오는 앱 설치 유도 레이어가 있는 웹 첫 화면만 확인했다. 실제 네이티브 앱 전체를 감사한 것으로 주장하지 않는다.

[그늘로 공식 홈](https://ttubeok.com/)은 그늘/볕뿐 아니라 언덕·계단 취향도 소개한다. 따라서 '계단/경사 추가'만을 고유 차별점이라고 주장하지 않는다. 시각 스타일을 복사하기보다 사용자 상황에 맞는 기준을 먼저 보여 주는 원칙을 참고한다.

## 접근성과 검증 한계

검색 지우기/실행, 스위치와 예산 버튼은 40~46px×44px. 아이콘 축소와 클릭 영역을 구분했다. 색 외에 텍스트/선택 상태를 유지한다. 키보드 Enter 검색과 버튼 라벨을 확인한다. 전체 WCAG 준수, 실제 스크린리더, 야외 GPS·기기별 백그라운드 추적은 미검증이다. 실제 신호 관측과 패턴 예측의 일치도는 이 디자인 점검 범위가 아니다.
