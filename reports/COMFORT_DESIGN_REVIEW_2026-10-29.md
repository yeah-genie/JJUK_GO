# 편한 길 중심 UI 독립 검토

2026-10-29 · BMAD UX 관점의 별도 에이전트 검토. 사용자 태블릿 스크린샷, 현재 `template.html`/`app.js` 변경분, 제품 방향과 인수인계를 읽었다. 이 검토자는 소스를 수정하거나 브라우저를 조작하지 않았다. 아래 화면 크기·터치 수락 검사는 구현 담당자의 실제 화면 검증이 필요하다.

## 판단

출발 카운트다운을 제거하고 시간 여유·계단·오르막의 선택을 앞세우는 방향은 사용자 요청과 맞는다. 스크롤 영역과 고정 행동 버튼을 분리한 구조도 기존의 `full` 상태 의존을 줄인다. 다만 **편한 길을 추구한다는 제품 방향과, 특정 후보가 실제로 덜 힘들다고 검증됐다는 주장은 구분해야 한다.**

## 구현 담당자와 조정한 원칙

- 작은 상승량 차이를 주 제목에서 과장하지 않도록 수정하기로 했다. 지형 커버리지와 입체구간 여부를 보고 표현하며, 표시 기준은 정확도 검증이 아닌 UI 기준으로 문서화한다.
- 계단 감소도 지도 검출 정보이며 전체 통행 가능성이나 실제 피로 감소를 입증한 것은 아니다.
- 신호 출발 비교는 선택적으로 여는 보조 기능이다. 주 화면에 초 단위 출발 지시나 현재 신호처럼 보이는 예측을 다시 올리지 않는다.
- 사용자 최신 지침대로 ‘올려서 비교’, ‘펼쳐서 확인’ 같은 조작 설명과 군더더기 안내 문구를 쓰지 않는다. 스크린리더용 조작 이름과 필요한 오류 복구 안내는 접근성 기능으로 유지한다.

## 배포 전 확인할 흐름

1. 같은 경로인 경우: 차이가 없다는 짧은 설명, 한 경로 카드, 시간 여유 선택, 고정 걷기 버튼이 모두 정상이다.
2. 다른 후보인 경우: 추가 예상 시간과 줄거나 늘어나는 부담이 계산값과 일치한다.
3. 미확인 자료가 있는 경우: 실제 계단0·정밀 경사·무정차·무장애 경로처럼 단정하지 않는다.
4. 긴 경로/긴 상세인 경우: 내용의 마지막까지 스크롤되고 CTA는 남는다. 예산을 바꾸거나 상세를 접은 뒤에도 스크롤이 잠기지 않는다.
5. 키보드: 패널 높이 버튼과 두 개의 상세 펼침을 각각 조작할 수 있고, 포커스가 고정 CTA 아래로 가려지지 않는다.

실제 피로 감소·현장 출입구·당일 신호 정확도는 이 디자인 검토에서 검증하지 않았다.
