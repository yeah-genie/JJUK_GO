# 편한 길 결과 화면 수정

2026-10-29. 사용자 Android 태블릿 스크린샷의 스크롤 잠김과 출발 카운트다운 중심 UI 피드백을 반영했다.

## 변경

- 결과 패널 중간 높이에서 `overflow:hidden`이 되던 규칙을 제거했다. 내용은 독립적인 세로 스크롤 영역, 걷기 버튼은 그 형제 footer다. 접힌 peek 상태는 버튼을 숨기며 중간/전체 높이에서 고정한다.
- 결과의 중심을 추가 예상 시간과 계단·오르막·신호 비교로 바꿨다. 같은 시간/+2/+5/+10분은 임시 UI 선택지다. 출발 초 카운트다운 및 불필요한 ‘올려서 비교’ 안내를 제거했다.
- 출발 시각 비교는 경로 정보 안의 별도 선택 상세로 옮겼다. 선택한 출발 기준과 ETA를 보이되 현재 실제 신호라고 표현하지 않는다.
- 같은 후보면 같은 길이라고 짧게 설명한다. 다른 후보의 불리한 조건도 숨기지 않는다. 선택 표시는 진한 테두리·노랑 선·체크로 구분한다.
- 지형 커버리지80% 이상, 입체구간 미확인 없음, 상승량 차이10m 이상일 때만 상승량 감소를 대표 문구에 쓴다. 10m는 표시용 임시 문턱이며 정확도나 피로 차이를 검증한 수치가 아니다.
- 터치/혼합 입력 태블릿에서 장식 폰 프레임을 없애는 반응형 규칙, 넓은 터치 화면의 오른쪽 패널, 실제 패널 위치에 따른 지도 여백 계산을 추가했다.
- QA가 찾은 닫힌 출발 상세 때문에 미확인 각주까지 숨기는 조건을 수정했다. 중첩 상세 화살표가 부모의 열린 상태를 따라가던 선택자도 정리했다.

## 검증

- Python 전체64개 통과(2.05초).
- 확장 Node VM 회귀 검사 통과: 시간 예산, 미확인 신호/후속 도착 위상, GPS 취소·대략 위치, 출입구 연결, 네트워크 재시도, 편한 길 표현.
- CUA 실제 브라우저 CSS390×844에서 예시 결과 기본/상세 확인. 내용648px/전체756px에서 기본 scrollTop0→107.46 이동, 버튼 하단832.18px로 화면844px 안 유지 확인.
- 브라우저 검사 스크립트는 새 UI에 맞춰 갱신했으나 이번 작업에서는 Playwright 스크립트를 실행하지 않았다. Node VM은 브라우저 검사와 다르다.
- 320px·태블릿 터치 입력의 실제 재현은 이번 회차 미완료다. 화면 크기 도구의 변경이 검사 탭에 반영되지 않아 해당 크기로 통과했다고 기록하지 않는다. Android 사용자 기기 터치 스크롤도 별도 확인이 필요하다.
- 실제 휴대전화 GPS, 현장 보행, 모든 서울 출도착 조합의 정확도 검증은 미완료다. UI 수정이 이 한계를 해결한 것은 아니다.
