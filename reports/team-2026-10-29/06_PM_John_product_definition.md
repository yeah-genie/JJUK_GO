### 1-5. 왜 지금까지 꼬였나 (원인 3개)
1. **비유를 기능으로 번역했다.** "나이키 걷기 버전"을 에이전트가 기록·속도 학습 화면 구현으로 해석했고, 사용자는 오후에 "걷기에 더 집중"이라고 정정했다. 정의가 사용자 문장이 아니라 에이전트의 번역 위에 쌓였다.
2. **가치를 교체하지 않고 누적했다.** 덜 멈춤 → 출발 타이밍 → 편한 길 → 내 페이스 → 장소+길 → 걷기 기록이 한 화면에 쌓였다(Mary 2-1: 약속 문구가 9번 바뀌었고 사용자 발언 기원은 2개뿐). 그래서 "복잡하고 정신없다"는 지적이 나왔고, 복잡함을 줄이다 차별점도 접혔다(BMAD_AUDIT).
3. **검증 안 된 입력 위에 약속을 얹었다.** 횡단보도 길이 없음, 녹색 최소 8초 고정, 실제 야외 보행 검증 0회인데 배리어 프리를 말하고 있었다. 차별성도 한 번도 같은 출도착에서 측정되지 않았다.
(부가: 최신 기능 코드는 `codex/refine-time-results` 브랜치에 있고 이 체크아웃은 구버전이라 서로 다른 화면을 이야기하게 된다. 사실 확인은 Mary 0절.)

## 2. '뚜렷한 차이'의 정의 [제안]

**정의: 같은 출발·도착을 넣었을 때, 일반 지도앱 결과에는 없는 숫자 2개 이상이 한눈에(스크롤 없이) 보이고, 그 숫자가 '내 걸음 속도'에 따라 달라지는 것.**

일반 지도앱이 보여주는 것(분·거리 위주)과 비교한다. 경쟁 앱의 신호·경사 반영 범위는 문서상 전체 확인이 안 됐으므로 "일반 앱에는 없다"고 단정하지 않고, **출시 전에 같은 출도착 20쌍을 직접 비교해 확인한다**(성공 기준 1).

| 화면에 보일 숫자 | 지금 가진 데이터로 | 비고 |
|---|---|---|
| 멈춤 횟수 (확인 N곳 / 모름 M곳) | **가능** (08~10시, 패턴 통과 교차로 2,352곳 범위) | 모르는 곳은 숫자에 합산하지 않고 '모름 M곳'을 같이 적는다. 평균 45초 가정이 있으면 '추정' 표시 |
| 예상 대기 합계(초) | **일부 가능** | 확인된 신호만. 미확인 대기는 총 시간에서 빠졌음을 표시 |
| 내 걸음으로 건널 때 남는 여유(초) | **가능하나 추정** | 신호 녹색 시간은 있고 **횡단보도 길이는 없음** → 가정값(추정 표시). 공공데이터(OA-21209 등) 확보 시 교체. 녹색 최소 8초는 가정 |
| 계단 수 | **일부 가능** | OSM 검출 기준. '0'은 "검출 0"이지 "없음"이 아님 → '확인된 계단 0'으로 표기 |
| 오르막 합계(m) | **일부 가능** | 약 120m 파생 지형이라 작은 차이는 믿기 어려움 |
| 걸리는 시간 차이(+n분) | **가능** | 내 속도 선택에 따른 계산 |

지금 **보여줄 수 없는 것**: 오늘·지금의 실제 신호(과거 패턴만) / 08~10시 밖 시간대 / 요일별 차이 / 엘리베이터·경사로·턱 유무 / 횡단보도 실제 길이 / 실제 대기 감소·피로 감소 효과(측정된 적 없음) / 경쟁 앱 대비 우위 증거 / 서울 모든 조합의 정확도(측정 안 됨). 이것들은 화면에서 '모름'이거나 아예 약속하지 않는다.

**솔직한 한계 [제안]**: 길이 같아도 숫자는 다르게 보인다는 점이 '뚜렷한 차이'의 전부다. 서울 300쌍에서 길이 달라진 비율이 19.9% 이하이므로, 길 자체의 다름은 차별점이 못 된다.

## 3. 1차 사용자, 장면, 배리어 프리

### 3-1. 1차 사용자와 장면 [가정]

- 검증: 실제 이런 사람 5명에게 목업과 실제 보행으로 확인한다(5절).

### 3-2. 배리어 프리의 대상과 약속 수준 [제안]
- **[사용자]** "배리어 프리"만 말했고 대상은 말하지 않았다. 아래는 모두 제안이다.
- 대상(1차): 걸음이 느린 사람, 고령자, 유모차·짐을 든 사람, 일시적으로 다리가 불편한 사람. **휠체어 이용자는 1차에서 제외 제안**: 엘리베이터·경사로·턱 자료가 없어 판단 재료가 없다.
- 약속 수준: **'참고 정보'**. "무장애 길"·"안전한 길"·"건널 수 있음" 같은 보증 표현은 쓰지 않는다. 화면에는 "내 걸음 기준 추정, 현장 확인 필요"에 해당하는 짧은 표시와 '모름'을 둔다.
- 쓰지 않을 표현: "뛰세요" 류, "안전", "보장", "무장애".
- 약속 수준 단계(올릴 때는 근거를 먼저 확보): ① 참고 정보(지금) → ② 공공데이터 횡단 길이 반영 → ③ 엘리베이터·경사로 통합 → ④ 현장 검증 후 지역 단위 표기.

### 성공 기준 (관찰 가능)
1. **차이 인식**: 일반 지도앱 결과와 우리 결과를 나란히 보여 주고 "뭐가 다른가요"를 물으면, 5명 중 4명이 숫자 차이 하나를 스스로 말한다.
2. **비교 사실 확인**: 같은 출도착 20쌍(08:40, 커버 구역)을 일반 지도앱 2개와 직접 비교해, 우리 화면에만 있는 숫자가 2개 이상인 쌍이 18쌍 이상이다. (이때 '일반 앱에 이미 있다'가 확인되는 숫자는 차별 목록에서 뺀다)
3. **현장 일치**: 5명이 실제로 걷고 표시된 멈춤 횟수와 실제 멈춤을 비교했을 때, 오차 ±1 이내인 구간이 대부분(기준은 첫 결과를 본 뒤 사용자와 합의).
4. **정직 표시 이해**: '모름'·'추정'을 확정 숫자로 오해한 사람이 0명(5명 대상).
5. **재사용**: 보행 테스트 후 7일 안에 스스로 다시 연 사람이 5명 중 2명 이상.

### 반증 조건 (이게 안 되면 방향을 바꾼다)
- 기준 1이 2명 이하 → '숫자 차별'을 접고 V1 원래 가치(출발 타이밍) 중심 복귀 또는 다른 차별 후보를 다시 연다.
- 기준 2에서 경쟁 앱에 같은 숫자가 이미 있음이 드러남 → 해당 숫자는 차별 주장에서 제외. 남는 차별이 1개 이하면 제품 정의를 다시 쓴다.
- 기준 3의 일치가 낮음(멈춤 횟수가 자주 틀림) → 신호 기반 숫자 약속을 철회하고, 신호 숫자는 '참고'로만 두거나 신호 축을 접는다.
- 기준 5가 0명 → 일회성 호기심이었다고 보고 첫 사용자 가설(3-1)부터 다시 검증한다.
- 위 어느 경우든 "수요를 확인했다"고 쓰지 않는다. 이 단계의 성공은 수요 증명이 아니라 '차이가 보이는가'의 확인이다.

## 6. 사용자에게 꼭 물어야 할 질문 (3개)

Mary의 5개 중 1(첫 사용자·장면)은 3-1의 가설로 검증하고, 5(공개 범위)는 기본값(서울 전체 제공 + '모름' 표시 + 지인 5명 보행 테스트)으로 진행하고 묻지 않는다.

**Q1. "배리어 프리"는 누구를 위한 것이고 어디까지 약속할까요?** (Mary 2)
- A. 걸음 느린 사람·고령·유모차·일시적 불편, 약속은 '참고 정보' (**기본 추천**) — 지금 가진 데이터로 지킬 수 있는 선.
- B. A + 휠체어 포함 — 엘리베이터·경사로 데이터를 먼저 구해야 하므로 MVP가 길어진다.
- C. '내 걸음에 맞춘다'는 접근 방식 이름일 뿐 특정 대상은 없다.

**Q2. 이미 만든 화면 중 무엇을 지울까요? 4-2의 판정(남김 1, 축소 5, 삭제 2)에 동의하시나요?** (Mary 3)
- A. 제안대로: 그냥 걷기·기록 삭제, 내 걸음·출발 시각·신호 상세·도착 카드 축소, 편한 길 비교 남김 (**기본 추천**).
- B. 기록은 남기고 나머지만 제안대로.
- C. 직접 골라 주세요. 이때 "코덱스가 영 별로"가 화면·기능·방향 중 어느 쪽인지 한 줄만 알려주시면 판정이 정확해집니다.

**Q3. 핵심 가치를 '내 걸음 기준 숫자'(멈춤 N + 건널 여유)로 하고 출발 시각은 보조로 내릴까요?** (Mary 4)
