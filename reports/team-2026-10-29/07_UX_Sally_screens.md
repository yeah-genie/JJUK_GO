## 1. John의 정의에 대한 반박·수정 (UX 관점)

John의 방향(내 걸음 기준으로 멈춤 횟수와 건널 여유를 숫자로)에는 동의한다. 다만 아래 6가지는 그대로 화면에 옮기면 사용자가 차이를 못 느끼거나 숫자를 오해한다.

| # | John의 정의 | 문제 | 수정 제안 |
|---|---|---|---|
| R1 | 켜는 순간 = 08:40 현관 앞, "내 위치로 출발" 누름 | 홈에는 숫자가 하나도 없다. 목적지를 넣고 눌러야 결과가 나오므로 **켜는 순간에는 차이가 안 보인다.** "내 위치로 출발"은 목적지가 비어 있으면 눌러도 갈 곳이 없다 | 홈의 '자주 가는 곳' 칩 안에 **숫자 2개를 미리 보여준다**(예: `집→역 · 멈춤 2곳 · 18분`). 칩 1탭 + "내 위치로 출발" 1탭 = 2탭으로 결과. 첫 실행(칩 없음)은 도착지 입력창이 열린다. 칩 숫자 계산이 무거우면 숫자 없이 칩만 둔다(fallback) |
| R2 | 시간대 08~10시 데이터가 전부인데 장면도 08:40 | 사용자가 오후 2시에 켜면 신호 숫자가 전부 '모름'이 되어 **차이가 사라진다.** 이것이 가장 큰 UX 위험이다 [가정] | 결과 화면 상단에 `출발 08:40` 시각 칩을 항상 보여주고, 신호 아는 시간(08~10시) 밖이면 "신호 모름" 상태(4-3)로 정직하게 표시한 뒤 `08:40로 보기` 1탭을 준다. 첫 데모는 08:40 예시로 고정하고 그렇게 표시한다 |
| R3 | "예상 대기 합계"와 "건널 여유"를 숫자로 | 여유를 **합하면** 의미가 없다(한 곳 +20초가 다른 곳 −2초를 덮지 않는다). 또 "여유 +4초"가 무슨 뜻인지 처음 보는 사람은 모른다 | 1순위 숫자는 합계가 아니라 **'가장 빠듯한 횡단 +n초'**(가장 작은 값) 하나. 뜻은 자세히에서 **막대 1개**로 보여준다(초록 막대 안에 내가 건너는 구간을 칠하고 남는 칸이 여유). 문장 설명은 쓰지 않는다 |
| R4 | 핵심 숫자가 곧 '건널 여유' | 횡단보도 길이 데이터가 없어 여유는 **전부 가정값 기반 추정**이다. 정직 규칙상 1순위 숫자가 전부 '추정'이면 가장 큰 숫자가 가장 약한 숫자가 된다 | 위계를 **'멈춤 횟수'(관측 이력 기반) > '가장 빠듯한 횡단'(추정)** 로 둔다. 둘 다 크게 보이되 왼쪽이 멈춤, 오른쪽이 여유(추정 표기). 공공데이터(OA-21209) 확보 후 여유 표기를 '확인'으로 올린다 |
| R5 | 내 걸음 속도 3단계 선택 | 라벨이 "느림/보통/빠름"이면 사용자(느린 걸음 포함 대상)에게 낙인이 된다. 별도 화면도 필요 없다 | 라벨 없이 **숫자 칩 `3.2 / 4.3 / 5.0` km/h**(codex 브랜치 값 0.9/1.2/1.4 m/s를 환산, Mary §4 기준). 결과 화면 안에서 바로 바꾸면 숫자가 즉시 바뀐다. 이것이 '내 걸음에 따라 달라진다'를 보여주는 가장 싼 장면이다 |
| R6 | 그냥 걷기·기록 삭제, 내 걸음 축소 | 동의한다. 다만 삭제하면 "걷기에 더 집중"이 **정의 안에서 어디에 있는지**가 비게 된다. 사용자의 정정 문장이 화면에서 보이지 않는다 | '걷기 집중'을 **걷는 중 화면을 1급 화면으로 만드는 것**으로 흡수한다(3-3: 다음 횡단까지 거리 + 도착 시 예상 + 내 걸음 기준). 이 해석이 맞는지는 사용자에게 한 줄 확인이 필요하다(8절) |

덧붙여: **로고 화면(약 2초)은 없앤다.** 켜는 순간이 약하다는 R1과 정면으로 충돌한다. 브랜드는 홈 상단 로고로 충분하다 [제안].

## 2. 화면 목록과 흐름

### 2-1. 최소 화면 (독립 화면 4개)

| # | 화면 | 한 가지 목적 | 비고 |
|---|---|---|---|
| 1 | **홈** | 도착지를 정하고 "내 위치로 출발"을 누른다 | 지도 + 하단 시트. 도착지 검색은 이 시트가 열리는 상태이지 별도 화면이 아니다 |
| 2 | **결과** | 같은 길에서 '내 걸음 기준 숫자'를 한눈에 본다 | 지도 + 하단 시트. 2단계: 요약 → 자세히(같은 시트를 펼침) |
| 3 | **걷는 중** | 다음 횡단보도에 내가 어떻게 도착하는지 본다 | 지도 크게 + 하단 작은 시트 |
| 4 | **도착** | 걷기를 끝내고 예상과 비교한다 | 최소 화면. 첫 데모에서는 맨 뒤로 미룬다(7절) |

### 2-2. 화면이 아닌 것 (상태·시트)

| 항목 | 처리 |
|---|---|
| 자세히(횡단보도별) | 결과 시트를 위로 펼친 상태. 시트 안은 스크롤 가능, 스크롤바 숨김 |
| 내 걸음 속도 | 결과·홈 시트 안의 숫자 칩 한 줄 |
| 출발 시각 | 결과 상단 `출발 08:40` 칩 → 누르면 작은 시트(+0/+5/+10분류). 큰 카드·별도 화면 없음 |
| 신호 정보 없는 곳 | 결과의 '모름 많음' 상태(4-3) |

### 2-3. 현재 화면의 합침·삭제 [제안]

| 현재 | 판정 | 이유 |
|---|---|---|
| 로고 화면 | **삭제** | 켜는 순간을 늦춘다 |
| 홈 | 유지·재배치 | 주 버튼 "내 위치로 출발", 칩에 숫자 |
| 경로 결과 | 유지·재설계 | 핵심 |
| 횡단보도 상세 | 결과 '자세히'에 **합침** | 화면 수 감소 |
| 출발 시각 추천 | 결과 상단 칩에 **합침** | 중심 금지(사용자 지적) |
| 신호 정보 없는 곳 | 결과 '모름' 상태에 **합침** | |
| 내 걸음 | **삭제**(칩으로 흡수) | R5 |
| 그냥 걷기 | **삭제** | John 판정에 동의 |
| 기록 | **삭제** | John 판정에 동의 |
| 걷는 중 | 유지·재설계 | 3-3 |
| 도착 공유 카드 | 도착으로 **축소** | 공유·랭킹 요소 없음 |

### 2-4. 흐름

```
홈 ──(도착지 선택/칩 1탭)──▶ 홈(도착지 채워짐)
홈 ──["내 위치로 출발"]────▶ 결과(요약)
결과 ──(시트 위로/"자세히")─▶ 결과(자세히) ──(아래로)──▶ 결과(요약)
결과 ──(속도 칩/출발 시각 칩)─▶ 같은 화면에서 숫자만 바뀜
결과 ──["걷기 시작"]──────▶ 걷는 중
걷는 중 ──["끝내기"]──────▶ 도착
도착 ──["홈으로"]────────▶ 홈
(결과·걷는 중에서 뒤로 = 한 단계 이전, 걷는 중에서는 확인 한 번)
```

| 일반 도보 안내 `18분 · 1.3km` | ③ | 회색 | 모르는 값 없음 (거리·시간은 계산값) |
| 내 걸음 칩 | ② | `3.2 / 4.3 / 5.0 km/h` | 바꾸면 ①②의 숫자가 즉시 바뀐다 |
| 출발 시각 칩 | ③ | `출발 08:40 ▾` | 누르면 작은 시트. 데모 기본값은 예시 시각이므로 `예시` 표시를 시각 칩 안에 둔다 |
| 걷기 시작 | 버튼 | `걷기 시작` | 하단 엄지 영역 |

쓰지 않는 것: 종합 점수·등급, "안전/무장애/보장", "뛰세요", "올려서 비교", 설명 카드, 긴 문장.

## 4. '차이가 한눈에 보이는' 장면 설계

### 4-1. 원칙 [제안]
- **경쟁 앱 화면을 지어내지 않는다.** 대비 대상은 `일반 도보 안내`, 곧 **시간·거리만 있는 일반적인 도보 안내**라고만 쓴다. 특정 앱 이름·로고·모양을 흉내 내지 않는다.
- 한 화면, 한 경로, 두 층: 위 층(회색, 작음)은 누구나 아는 `18분 · 1.3km`, 아래 층(노랑 선으로 구분)은 `쭉고가 더하는 것`.
- 사용자가 설명을 읽지 않아도 **"회색 층에는 없던 숫자가 노랑 층에 있다"** 가 눈으로 보여야 한다.

### 4-2. 같은 경로 한 장면 (결과 요약)

```
 지도 위 경로선
  일반 도보 안내가 보여주는 것:  ┄┄┄┄┄┄┄┄┄┄┄┄  (회색 점선, 마커 없음)
  쭉고가 더하는 것:              ━━■━━▶━━■━━?━━  (노란 실선 + 멈춤 ■ / 통과 ▶ / 모름 ?)

 시트
  일반 도보 안내   18분 · 1.3km                 ← 회색, 작음
  ───────────── 쭉고가 더하는 것 ─────────────
  멈춤 2곳 (+모름 1곳)   |   가장 빠듯한 횡단 ~+3초   ← 크고 진함
  계단 확인 0 · 오르막 ~51m 추정 · 신호 대기 ~1분20초
```

- 지도에서는 같은 경로선 위에 **마커가 있느냐 없느냐**가 곧 차이다. 마커 모양(■ ▶ ?)은 색에 의존하지 않는다.
- 시트에서는 **크기·진하기 차이**로 위계를 만든다. 회색 층은 일부러 작게 둔다. 두 층은 같은 카드에 담지 않는다(구분선 + 라벨).

### 4-3. 내 걸음에 따라 달라진다 (가장 싼 증명)
`내 걸음 [3.2 | 4.3 | 5.0]` 칩을 누르면 **회색 층 `18분`은 같이 바뀌지만 노랑 층 숫자(멈춤·가장 빠듯한 횡단)도 함께 바뀐다.** 사용자가 손가락으로 직접 확인하는 장면이다. 숫자가 바뀔 때 0.2초 숫자 롤 정도의 움직임만 쓰고, `줄어듦 −1곳`처럼 설명하는 글은 붙이지 않는다. 움직임 줄이기 설정이면 즉시 교체한다.

### 4-4. 두 가지 대비 상태
- **모름 많음(신호 모름 ≥ 절반)**: ①을 `멈춤 모름`으로 바꾸고 아래에 `신호 6곳 모름`. 이때 노랑 층의 주인공은 `계단·오르막`(확인/추정)이 된다. 차이가 줄어드는 것을 숨기지 않는다.
- **통과 위주**: `멈춤 0곳`이어도 같은 레이아웃. 칭찬 문구는 쓰지 않는다.

### 4-5. 사용자 확인 전용 비교판 (제품 화면 아님) [제안]
사용자에게 "차이가 보이나요?"를 묻기 위한 **한 장짜리 비교 이미지**를 만든다. 왼쪽 `시간·거리만 있는 일반적인 도보 안내`(회색 숫자 2개), 오른쪽 `쭉고`(숫자 5~6개). 제품 코드에 넣지 않는다. 경쟁 앱 캡처를 쓰지 않는다.

## 5. 신호·횡단 여유: 요약 → 자세히, 그리고 표기 규칙

### 5-1. 2단계 구조

| 단계 | 위치 | 보이는 것 | 사용자 행동 |
|---|---|---|---|
| **요약** | 결과 시트 기본 | 멈춤 `N곳`(+모름), 가장 빠듯한 횡단 `~+n초`, 보조 3열 | 한눈에 읽고 "걷기 시작" |
| **자세히** | 같은 시트를 위로 펼침 / `자세히` 탭 | 횡단보도 목록(경로 순서) + 계산 기준 | 스크롤(바 숨김)하며 곳곳을 확인 |

### 5-2. 자세히의 한 행 (높이 64px, 터치 44px 이상)

```
┌──────────────────────────────────────┐
│ 1  역삼역 앞                          │  이름 16px
│ ■ 멈춤 ~40초     ▕▓▓▓▓▓▓░░░▏ ~+4초   │  상태(모양+글자) / 막대 / 여유
└──────────────────────────────────────┘
```
- **막대**: 전체 폭 = 초록 시간. 칠한 부분(아스팔트) = 내가 건너는 데 필요한 시간. 남는 빈 칸(윤곽선) = 여유. 막대 오른쪽에 숫자 `~+4초`. 모자라면 칠한 부분이 막대 끝을 넘고 빗금으로 표시하며 숫자는 `~−2초`.
- **상태**: `■ 멈춤` / `▶ 통과` / `? 모름`. 색은 보조일 뿐 모양과 글자가 필수다.
- 행을 탭하면 그 횡단보도를 지도에서 강조한다(별도 화면 없음).
- 하단 접힘 `계산 기준`(1줄 제목): 기준 시각, 내 걸음 속도, 횡단 길이 가정, 초록 최소 가정, 신호 출처(과거 패턴). **가정값의 구체 숫자는 개발·데이터 쪽이 정하며, 이 문서는 표기 방식만 정한다.**

### 5-3. 범례 1개 (확인 / 추정 / 모름)

화면 어디서나 같은 3가지 표기만 쓴다. 범례는 자세히 상단에 **한 줄**로만 보여주고, 첫 사용 때 한 번 펼쳐 보인다(이후 `?` 아이콘 44px).

| 의미 | 쓰는 때 | 글자 모양 | 보조 표시 | 예 |
|---|---|---|---|---|
| **확인** | 관측된 신호 이력·지도 데이터로 직접 센 값 | 굵은 글자, 접두 없음 | 실선 밑줄 없음, 채운 마커 ■ ▶ | `멈춤 2곳` · `계단 확인 0` |
| **추정** | 가정값을 써서 계산한 값(횡단 길이 등) | `~` 접두 | 점선 밑줄 + 작은 `추정` 칩 | `~+3초` · `~51m 추정` |
| **모름** | 데이터가 없어 계산 못 함 | `모름` 글자 그대로 | 빗금 칩(회색 윤곽) + 속이 빈 마커 `?` | `모름 1곳` |

규칙:
1. 모름은 숫자에 합산하지 않고 항상 옆에 따로 적는다.
2. 추정이 섞인 합계는 추정으로 표기한다(확인 + 추정 = 추정).
3. 세 표기 모두 **색 없이** 구분된다(접두·밑줄·빗금·모양).
4. '가정'이라는 말은 `계산 기준`에서만 쓰고 숫자 옆에는 쓰지 않는다(범례 1개 유지).
5. 신호는 과거 패턴 기반이다. 실시간 표현(`지금`, `곧 바뀜`)은 쓰지 않는다.

### 색 (기존)

## 8. 사용자에게 보여줘 확인받을 순서 (첫 데모에서 무엇부터)

원칙: **차이가 보이는지가 먼저, 나머지는 그다음.** GPS·실기기 없이 만들 수 있는 것부터 보여준다.

| 순서 | 만들 것 | 이유 | 사용자에게 물을 것 (선택지) |
|---|---|---|---|
| **1** | **결과 화면 정적 3상태** (보통 / 모름 많음 / 내 걸음 칩 3단) + 4-5의 비교판 1장 | 정의가 맞는지 여기서 판가름. GPS 불필요, 가장 싸다 | "일반 도보 안내와 뭐가 다른지 보이나요?" A. 보인다 / B. 숫자는 보이는데 와닿지 않는다 / C. 안 보인다. **C면 정의를 다시 연다**(John 반증 조건 1과 연결) |
| 2 | **자세히** (막대 한 행 + 범례 한 줄) | 숫자를 이해시킬 수 있는지 | "막대와 `~+3초`가 무슨 뜻인지 설명 없이 알겠나요?" |
| 3 | **홈** (칩에 숫자 + "내 위치로 출발") | R1 확인. 주 버튼 위치·문구 확정 | 칩 숫자 미리 보기를 쓸까요? A. 쓴다 / B. 칩만 |
| 4 | **걷는 중** (가짜 위치 시연) | "걷기에 더 집중"의 해석 확인 | "걷기 집중 = 이 화면(다음 횡단 + 도착 시 예상)이 맞나요?" A. 맞다 / B. 기록·페이스 쪽이다 / C. 다른 것 |
| 5 | **도착** | 마무리, 가장 낮은 우선순위 | |

기타 사용자 확인이 필요한 것(이 문서는 임의로 정하지 않았다):
- 첫 실행 시 최근 도착지를 미리 채울지(R1). 낙인 없는 숫자 칩(R5)으로 가도 되는지.
- 로고 화면 삭제(R1 부가).
- 08~10시 밖에서는 `신호 모름` 상태로 보여주는 것을 받아들일지(R2).

데모에서 **표시할 것**: 숫자는 예시/계산 기준임을 `계산 기준`과 시각 칩의 `예시`로 표시한다. 실제 야외 보행·기기 safe-area·스크린 리더는 아직 검증되지 않았다 **[모름]**.
