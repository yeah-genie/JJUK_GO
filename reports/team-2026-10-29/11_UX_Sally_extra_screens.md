# 11. 추가 화면 판단과 UI 시안 (Sally, UX 디자이너)

2026-10-29. 사용자 요청: "시안 4장이 맘에 든다 … 어떤 화면을 더 만들지 고민해서 UI만 만들어봐." 이 문서는 **(1) 어떤 화면이 더 필요한지 판단**하고 **(2) 그 화면의 UI만** 시안 4장과 같은 시각 언어로 만든 결과다. 앱 로직·`docs/prototype/`은 건드리지 않았다. 아래 화면 선택·문구·우선순위는 모두 **[제안]**이며 사용자가 승인한 것이 아니다.

- 갤러리: `docs/design/screens/index.html` (정적 HTML 한 장, JS·외부 이미지·웹폰트 없음, 18프레임)
- 캡처: `docs/design/screens/png/*.png` (프레임당 1장, 모두 110KB 이하)
- 프레임 id: `#f-<이름>`. 캡션 제목을 누르면 `:target`으로 크게 보인다(JS 없음).

## 1. 판단: 어떤 화면이 더 필요한가

기준은 하나다. **사용자가 막히는 순간에 화면이 없으면 앱이 숫자를 지어내거나 조용히 실패하는가.** PRODUCT_SPEC §9의 실패 상태 표와 §3·§5·§6·§7이 요구하는데 시안 4장에 없는 것을 먼저 골랐다.

상·중 12개를 만들었고(프레임으로는 15장 + 360×640 변형 3장), 만들지 않은 것의 이유는 다음과 같다.

- **13 후보가 같을 때:** 두 행을 만들지 않고 한 행으로 줄이는 일이라 결과 화면(#3)의 `.route-row` 하나만 남기면 된다. 새 레이아웃이 아니다.
- **14 빈 시간대·요일:** 현재 수치 gate가 fail-closed여서 일반 모드는 이미 #3의 `여유 계산 준비 중`·`정보 없음`으로 보인다. 별도 화면은 날짜·요일 일반화(미완료 항목)가 생긴 뒤에 의미가 있다.
- **15 출입구 연결 3단계:** 35m·100m는 내 이전 안(09 §6-3)과 Winston의 가정값이고 PRODUCT_SPEC에는 `연결되는 보행 경로를 찾지 못했어요`와 `실제 출입구/다른 지점 선택`만 있다. 근거 없는 숫자를 UI에 굳히지 않으려고 보류.
- **16 경로 없음·지도 실패:** `.notice`와 `.empty-state` 컴포넌트를 그대로 쓰면 되는 문구 교체라 새 화면이 아니다(#2, #12가 같은 패턴). 구현 때 문구(§9)만 붙이면 된다. 빈 지도 위에 가짜 경로를 그리지 않는다는 규칙은 유지.
- **17 보호자 비교:** 09 문서에서 내가 제안한 `걸음 2칸 저장`은 PRODUCT_SPEC(계정 필수 없음, 독립 프로필 화면 금지, 직접값은 설정 하위) 범위를 넘는다. 승인 없이 화면을 만들면 제안을 결정처럼 보이게 하므로 만들지 않았다. 사용자가 원하면 별도 논의.
- **삭제 확정 항목**(독립 그냥 걷기·운동 기록·배지·공유 카드·출발 카운트다운·시간 막대·대중교통)은 후보에도 올리지 않았다.

## 2. 앱 흐름도 (텍스트)

```
첫 방문 ─ 설문 1/2 (승인 시안) ─ 설문 2/2 [#1] ─ 홈
               └ 건너뛰기 ──────────────────────┘ (어느 단계에서나)

홈 (승인 시안)
 ├ 검색창 ─ 검색 입력·결과 [#12] ─ 결과 없음 [#12] / 지도에서 도착 고르기
 ├ 내 위치로 출발 ─ 위치 권한 안내 [#2a] ─ (허용) 결과
 │                    └ 거부·실패 [#2b] ─ 지도에서 출발 선택 / 다시 시도
 ├ 설정(⚙) ─ 걸음 설정 (승인 시안)
 │             ├ 직접 정하기 [#7] ─ 적용 ─ 걸음 설정
 │             ├ 처음 답변 수정 ─ 설문 1/2 → 2/2 (draft, 취소 시 보존)
 │             └ 학습 초기화 ─ 초기화 확인 [#8] ─ 취소/초기화 ─ 걸음 설정
 └ 최근 찾은 곳 ─ 결과

결과 (승인 시안은 학습 반영 예시 / 학습 부족 [#3])
 ├ 계산 기준 ⓘ ─ 계산 기준 시트 [#4]
 ├ 조건 조정 ─ 조건 조정 시트 [#5] ─ 적용(경로 재계산)/취소 ─ 결과
 │               └ 걸음 설정 ›
 ├ 정보 없는 횡단 N곳 › ─ 펼침 [#9] ─ 횡단 하나의 상세 [#10]
 └ 걷기 시작 ─ 걷는 중 [#6]
                ├ 위치 끊김 ─ 측정 중지·다시 연결 [#11] ─ 다시 연결 ─ 걷는 중
                └ 안내 종료 ─ 결과 또는 홈
```
#번호는 위 판단표의 번호. `#2a/#2b`는 같은 후보의 두 프레임.

## 3. 화면별 설명

모든 프레임은 390×844(베젤 없음). 프레임 안 오른쪽 아래에 `시안`(또는 숫자가 나오는 화면은 `시안용 예시`) 표식이 있고, 프레임 밖 캡션에 이름·상태·크기·PRODUCT_SPEC 절·프레임 id가 있다.

| 프레임 id | 보이는 것 | 정직 표시·판단 |
|---|---|---|
| `onboarding-2-select` | `2 / 2` 진행 선, 질문 `오늘 함께하는 것이 있나요?`, 체크박스 6행(복수), `완료` | 복수 선택이라 원형 라디오가 아니라 **네모 체크**. 안내는 `계단 피하기 추천에만 참고해요`(§3 범위 안). 진단·나이는 묻지 않음 |
| `onboarding-2-none` | `없음`만 체크 | `‘없음’을 고르면 다른 선택이 풀려요`. 미선택과 명시적 없음이 다름 |
| `location-ask` | 홈이 어두워지고 시트: `내 위치는 허용할 때 연결해요`, `위치 허용하기`, `지도에서 출발 선택` | 시트는 사용자가 `내 위치로 출발`을 누른 뒤에만. `허용하면 브라우저가 한 번 더 물어봐요`로 OS 허가와 구분 |
| `location-denied` | 출발 `위치 연결 안 됨`, 지도에 **내 위치 점 없음**, 인라인 안내 `위치를 연결하지 못했어요`, `다시 시도`, 주 버튼 `지도에서 출발 선택` | 토스트가 아니라 화면에 남는 안내. 검색·설정은 그대로 |

| `result-unknown-list` | 위 화면에서 `정보 없는 횡단 2곳`을 펼침. 행마다 이름과 이유(`신호 기록 없음`, `횡단 길이 미확인`) | 지도의 점선 `?`와 같은 모양. 0초·0회로 바꾸지 않음. 지도는 줄어들지만 `?` 표식이 보임 |
| `calc-basis` | 시트: 걸음 속도 `임시`, 신호 시간 `기록`(실시간 아님), 신호 방향 `? 미확인`, 횡단 길이 `~ 추정`, 계단·경사 `~ 추정`, 정보 없는 횡단 `? 미확인` | 상태를 **색이 아니라 태그의 테두리 모양**(실선/점선/파선)과 글자로 구분. 기본 화면의 긴 면책을 대신하는 자리 |

## 4. 재사용 컴포넌트 (클래스 이름은 DESIGN_SYSTEM §5와 맞춤)

## 5. 눈으로 확인한 내용 (캡처 직접 열람)

18장을 `docs/design/screens/png/`에 저장한 뒤 Read로 열어 봤다. 처음 캡처에서 찾아 고친 것:

1. **버튼이 노랑으로 안 칠해지고 글자만 보임**(location-ask 등) — 공통 `button` 리셋이 `.btn-primary`보다 우선했다. `:where()`로 리셋해 해결.
2. **설문 제목·부제 여백 사라짐**(onboarding) — 같은 원인(`h1`/`p` 리셋). 해결 후 28px 제목이 한 줄로 들어옴.
3. **`편한 길 후보`가 3줄로 쪼개짐**, `여유 계산 준비 중`이 `준비`/`중`으로 어색하게 끊김 — 경로 행 열 폭을 조정하고 `word-break:keep-all` 적용.
4. **지도 라벨이 내 위치 점·확대 버튼과 겹침**(`대학로`, `마로니에공원`, `서울대`) — 라벨 위치 이동, 병원 면 위 라벨 삭제.
5. **횡단 상세의 확대 지도에서 글자·표식이 지나치게 커짐** — 라벨 크기를 변수(`--ml`)로 줄이고 횡단 표시를 줄무늬로 교체. 맨 아래 근거 행이 잘려 압축하고, 맨 아래 `시안용 예시` 표식이 행과 겹치던 것은 스크롤 본문 아래 30px를 비워 해결.
6. **걷는 중에서 내 위치 점이 길에서 떨어져 보임** — 지난 길/남은 길의 분기점을 내 위치로 수정.
7. 360 변형에서 확대/축소 버튼이 지도를 가림 — 숨김.

자동 점검(Playwright로 모든 프레임 계측): 보이는 모든 버튼·링크·선택 행·슬라이더가 44×44px 이상(토글은 `::after`로 터치 영역 확장, 360 변형에서 숨긴 확대/축소만 0), 본문 글자 12.5px 미만 0, 프레임 밖으로 넘치거나 잘리는 가로 글자 0, 갤러리 페이지의 가로 스크롤은 1300px·390px 폭 모두 0. 스크롤바는 CSS로 숨김. PNG 최대 약 110KB. 이 확인은 정적 HTML의 렌더에 대한 것이다.

시안 4장과의 일치: 면 색·구분선·노랑·차선 두 획 로고·행 구분선·노란 주 버튼(반경 12px)·`시안` 표식 위치·큰 카드 없음은 시안과 같은 방식으로 맞췄다. 정직하게 다른 점: (a) 시안은 입력 외곽이 옅은 선이지만 나는 DESIGN_SYSTEM 접근성 기준에 따라 `--control-line`을 썼다. (b) 시안 1/2는 아무것도 안 골랐는데 `다음`이 노랑이지만 PRODUCT_SPEC §3은 `다음` 비활성이라 2/2는 스펙을 따랐다(1/2는 다시 그리지 않음).

## 6. 한계

- **글꼴:** 이 샌드박스에는 Pretendard·Noto Sans KR·Apple SD Gothic Neo가 없어 대체 한글 글꼴로 렌더된다. 글자 폭·굵기가 실기기와 다를 수 있다(특히 `쭉고`의 굵은 로고 글자). 실기기·실제 글꼴 확인은 안 했다.
- **지도는 장식이다.** 시안 4장이 쓴 지명(혜화역·서울대병원 등)을 그대로 따온 CSS/SVG 단순화 그림이며 실제 지리·보행 가능성·횡단 위치가 아니다. 실제 지도 타일을 쓰지 않았다.
- **숫자는 전부 가상**이다. `~18분`, `+3분`, `~4초`, `1.0m/s`, `0.9km`, `650m` 등은 시안용 예시이고, `crossing-detail`은 수치 gate를 통과한 **미래 예시**다. 실제 앱의 현재 자료로는 숨겨진 상태다. 슬라이더 최솟값·최댓값(1.5–5)과 추가시간 칩 값은 구현 모듈이 정하기 전의 자리표시값이다.
- **정적 화면만 그렸다.** 포커스 링·`aria` 흐름·키보드 이동·200% 글 확대·768/가로 레이아웃·reduced-motion은 이 갤러리에서 검증하지 않았다(`role`/`aria-*` 속성은 마크업에 넣었으나 동작 검증 아님). 토글·슬라이더는 JS가 없어 움직이지 않는다.
- **사용자 확인이 필요한 제안:** 설문 2/2 부제 문구, 초기화 시트의 버튼 위계(취소=노랑), 걷는 중의 `종료`를 윤곽 버튼으로 둔 것, `조건 조정`의 칩 값, 보호자 비교를 만들지 않은 판단.
- 이 갤러리 HTML은 반복 컴포넌트를 쉽게 맞추려고 임시 스크립트로 생성했고(저장소에는 넣지 않음), 산출물 `index.html`만 남겼다. 이후 수정은 이 파일을 직접 고치면 된다.
- 앱 구현·배포·실기기 검증은 하지 않았다. push도 하지 않았다.
