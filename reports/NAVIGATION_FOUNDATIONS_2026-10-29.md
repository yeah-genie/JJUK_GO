# 실사용 길찾기 기반 1차 수정

2026-10-29 · 사용자 ‘아무 조합이나 정확한 길찾기는 아직 아니냐’ 질문 후 출발지/시간/통행경로/GPS/보행 검증 순서에 ‘시작’ 승인. 기존 디자인과 공개 이력 기반은 유지한다.

## 변경

- 최초 출발·도착을 비운다. 목적지만 고르면 출발지 검색을 이어서 요청한다. 예시 경로 버튼만08:40 예시를 사용하고, 일반 장소 조합은 현재 기기의 시각을 기준으로 계산한다. 필요한 신호 시간대 파일도 경로 거리/출발 시각에 맞춰 읽는다. 실제 당일 신호를 관측했다는 뜻은 아니다.
- 모르는 신호는45초/곳 가정을 경로 비교·화면 시간·뒤 신호 도착 계산에 함께 포함한다. 예산 비교의 중복45초 가산은 제거했다. 빠른 후보도 세 후보의 동일한 최종 시뮬레이션으로 정한다. 이 가정은 통계적 오차 범위나 실제 대기시간 보장이 아니다.
- 출발·도착은35m 이내의 지상 보행망에 연결한다. 먼 곳을300m까지 직선으로 붙이던 동작을 막았다. 도로 중간 지점은 기존 도로선을 분할해 붙이고 길이·형상을 보존한다. 신호/계단/입체구간 중간에는 임의로 시작점을 만들지 않는다. 출입구·담장·현장 통제가 검증됐다는 뜻은 아니다.
- 지도 요청 실패 캐시를 지워 다시 찾을 수 있게 했다. 일부 조각에 반대쪽 끝점이 없는 도로는 시작점 연결 대상에서 제외한다. 잘못된 좌표·계산 실패를 숫자NaN으로 표시하지 않고 경로 확인 실패로 처리한다. 비동기 이전 검색 결과가 새 검색을 덮어쓰지 않도록 요청 식별자를 비교한다.
- GPS 요청 중 화면을 바꾸면 대기 상태를 해제하고 늦은 응답을 무시한다. 상태 메시지도 현재 화면에만 표시한다. PC 대략 위치(최대1km 오차)는 지도의 후보로 확인하게 하고 자동으로 출발 확정하지 않는다. 실제 걷기 진행은50m 이내 오차의 신선한 위치만 사용한다.
- 경로 이탈 시 ‘내 위치에서 다시 찾기’를 제공한다. 현재 위치가30초보다 오래됐거나 불확실하면 다시 연결하도록 안내한다. 사용자가 누르면 현재 위치→기존 목적지로 재계산한 결과를 검토한다. 백그라운드 자동 추적/자동 반복 재탐색은 아니다.
- 지도 모양의 전후 약12m 방향을 비교해 가까운 좌/우회전, 검출 계단/신호를 다음 안내로 표시한다. 정확한 위치가 연속2회 도착지 근처에 잡히면 출입구 확인 안내를 표시한다. 음성 안내나 현장 표지 검증은 포함하지 않는다.
- 출발 비교 목록은 같은 선택 경로에서 시간만 바꾼다. 선택 후 다른 길로 바뀌던 경로 일치 문제를 줄였다. 요약의 고정10월28일 날짜와 실제 걸은 기록처럼 읽히는 표현도 정리했다.

## 검증

- Python64개 통과.
- Node VM: 미선택 출발지→검색, 미확인45초 포함/뒤 신호 도착 위상, 시간예산 중복 방지, 도로 중간 연결 후 전체 경로 좌표/시간 유한값, 지도 경계의 없는 끝점, 먼 연결 거부, 네트워크 재요청2회, GPS 화면 전환/늦은 응답/대략 위치 정책, 재탐색 목적지 보존, 좌회전·계단 안내를 확인했다.
- 내장 브라우저: 청계광장 목적지→출발지 확인→서대문역 선택→현재 시각 기준 정상 시간·경로 표시를 확인했다. 중간에 찾은 함수 이름 가림과 도로 좌표 형식 불일치를 수정하고 재검증했다.
- 실제 휴대전화 GPS 이동·야외 보행 비교는 수행하지 않았다. 임의 서울 조합 전부의 성공률·오차를 측정한 것도 아니다. 일반 검색은 약1.7만 OSM 장소 범위이고 보행망 누락/실제 출입구·공사/방향 매칭/거친 지형은 여전히 한계다.

## 다음 검증

휴대전화에서 평지·계단·신호가 있는2~3개 짧은 구간을 실제 걸으며 출발/도착 연결, GPS 오차·이탈, 안내 방향, 예상/실제 소요 차이를 비교해야 한다. 그 결과 없이 네이버/카카오 수준 정확도를 주장하지 않는다. 시간 입력/색상 재디자인과 일별 예약 활성화는 별도 범위다.

코드와 공개 배포 식별자는 인수인계에 최종 확인 후 기록한다.
