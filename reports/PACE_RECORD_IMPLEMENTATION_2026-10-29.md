# 걸음 속도 추정과 걷기 기록 구현

2026-10-29 (Asia/Seoul). Claude 작업. 사용자 요청: "codex 브랜치에서 이어서 해. 속도 추정이랑 걷기 기록부터 만들어."

## 배경

사용자 제품 정의(10/29): **배리어 프리 + 나이키 런의 걷기 버전 + 일반 지도앱의 짬뽕.** 세 축을 잇는 공통 변수가 '내 걸음 속도'라고 보고(에이전트 해석), 속도 추정과 기록부터 만들었다. 같은 속도 값이 도착 예상·신호 도착 시각 계산(지도앱), 페이스 기록(걷기 기록), 느린 걸음 계산(배리어 프리)에 함께 쓰인다.

## 계산 방법 (`docs/prototype/src/app.js`의 '내 걸음' 절)

- **쓰는 위치:** 오차 25m 이하만 쓴다. 30초 넘게 끊긴 사이는 세지 않는다.
- **20초 단위로 잰다.** 2초 간격 위치로 바로 재면 좌우로 흔들린 GPS 오차까지 걸은 거리로 더해져 빠르게 나온다. 시험에서 1.25m/s 걸음이 1.57m/s로 나와 고쳤다.
- **멈춤:** 두 위치 오차의 평균(최소 8m) 안에 머문 채 10~20초가 지나면 멈춘 구간이다. 기다리는 시간은 0.8m/s로 걷는 사람도 오차 원을 벗어났을 시간이라 느린 걸음을 멈춤으로 잘못 세지 않게 했다. 걷다가 멈춘 구간이 나오면 멈춤 1번.
- **걷기가 아닌 구간:** 2.2m/s(약 7.9km/h)보다 빠른 구간은 차량 등으로 보고 뺀다. 뛰기를 권하지 않는 원칙과 맞다.
- **속도를 내는 조건:** 1분, 50m 이상 걸었을 때만. 그 전에는 '—'.
- **내 속도에 섞기:** 새 기록을 걸은 시간만큼 무게를 두어 평균한다. 한 번의 기록은 최대 30분, 예전 값은 최대 1시간 무게라 최근 걸음이 반영된다. 0.5~2.2m/s 범위로 자른다.
- **기록 저장:** 30초·30m 이상 걸었을 때만. 마지막 20초 미만 구간도 끝낼 때 더한다.
- **개인정보:** 기기 localStorage에 속도 숫자와 기록 요약(시각·도착지 이름·시간·거리·페이스·멈춤)만 저장한다. 위치 좌표는 저장하지 않는다(시험으로 확인). 최근 30개만 남긴다.

## 검증

- `node scripts/check_walk_logic.cjs` 통과. 추가한 시험:
  - 1.25m/s 3분 걷기 → 20초 서기 → 1분 걷기, 오차 8m에 좌우 ±3m 흔들림: 속도 오차 0.06m/s 이내, 멈춤 1번, 거리 300m±15m
  - 제자리 흔들림은 걸은 거리 0
  - 8m/s 이동은 제외
  - 오차 60m 위치는 버림
  - 40초 걷기는 기록은 남기되 속도 없음
  - 섞기 계산(1.0과 1.4를 같은 시간 → 1.2), 범위 자르기
  - 기록에 좌표 없음
- `node scripts/check_pace_browser.cjs` (새 파일, 실제 서울 지도·가짜 GPS·시계 앞당김) 390×844, 360×640 통과:
  - 그냥 걷기 1.1m/s → 1.08m/s(3.9km/h)로 추정, 멈춤 1번, 지도 확대 16.5
  - '천천히'를 고르면 결과 화면 걷기 시간 = 경로 길이 ÷ 0.9
  - 경로 걷기 후 도착 카드에 '걸린 시간'·평균 페이스 표시
  - localStorage에 좌표 없음
  - 스크롤바 0, 가로 넘침 없음, 페이지 오류 0
  - 3회 연속 통과
- `python3 -m pytest -q` 64 passed. `node scripts/check_prototype_ui.cjs` 통과.
- `node scripts/check_walk_browser.cjs`는 78행에서 시간 초과로 실패한다. 원인은 시험의 가짜 GPS 위치(서울광장 126.97799, 37.56562)가 보행로에서 35m 넘게 떨어져 결과 화면이 '출입구 가까이에서 골라 주세요'를 띄우고 걷기 버튼이 숨는 것이다. 이번 변경 전 코드에서도 이 환경에서 같은 시험이 실패했다(75행). 고치지 않았다.

## 같이 바꾼 것

- 결과 시트에 다시 생긴 얇은 스크롤바 표시를 지웠다. 사용자 규칙: "스크롤바 절대 만들지 마". 스크롤 자체는 그대로 된다.
- 지도가 아직 불러오는 중에 화면을 옮기면 홈의 '전체 구역 맞춤'이 늦게 실행돼 다른 화면의 지도를 덮던 문제를 고쳤다(홈 화면일 때만 실행).
- 걷는 중 위쪽 칸 제목 '다음 신호 횡단보도' → '다음 안내'(회전·계단 안내도 나오므로).

## 한계와 다음 후보 (제안, 승인 아님)

- 실제 휴대전화로 걸어 본 검증은 하지 않았다. 화면이 꺼지거나 앱이 백그라운드로 가면 웹 GPS가 멈출 수 있다.
- 신호 대기 중 멈춤과 다른 멈춤을 구분하지 않는다.
- 배리어 프리 연결 후보:
  - 횡단보도마다 '이 걸음 속도로 초록 안에 건널 수 있나'(횡단 길이 ÷ 내 속도 vs 초록 시간)
  - 천천히 모드에서 MIN_GREEN을 횡단 길이에 맞게 늘리기
- 공개 배포(Vercel)는 하지 않았다.
