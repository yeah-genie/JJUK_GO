추가 공개된10/28 파일도 시도했다. 최초 수신은1,009,272,004바이트의 불완전 ZIP이었고, 이후 HEAD는1,544,063,650바이트를 안내했다. 재시도에서도 약1.01GB의 불완전 응답 또는 RemoteDisconnected가 발생했다. Range 요청도206이 아닌200으로 돌아왔다. **원인은 확정하지 못했으며10/28은 가져오기/배포에서 제외했다.** 정상14일 데이터를 덮어쓰지 않았다. 실패 부분파일도 정리했다.

## 앱 연결

- 기존 노랑/아스팔트 디자인, 지도와 걷기 흐름을 유지했다. 예전4개 내장 신호 대신 외부 정적 패턴 파일을 읽는다.
- 방향·날짜·시간대별 최소400관측, 학습 주기2회 이상·위상90% 이상·불순도2% 이하, 같은 날 뒷부분100표본 이상·상태 일치95% 이상 패턴만 사용한다. 후보 주기는 학습 구간의 초록 종료 간격에서 구한다.
- 각 방향/시간대는 가장 최근에 통과한 날짜를 사용한다. 시간대 밖·방향 미확인·자료 실패는 미확인으로 취급한다. 방향을 모르는 교차로 노드에 임의의 기본 방향을 대입하지 않는다.
-24개 시간대 파일로 나누고 기존08:40 기준 데모에 필요한08~10시만 받는다. 앱은 원본 ZIP이나 전체 보행 아카이브를 받지 않는다.
- 기본 결과에 ‘공식 이력 기준·실시간 아님’을 표시한다. 신호 상세에는 해당 패턴의 실제 날짜·시간 범위·관측량·동일 날짜 검증률을 표시한다. 확인 화면 예: 세종대로사거리1821,10/17 08시,17.1분 관측,뒷부분 상태 일치99%.
- 이는 **오늘의 예측 정확도, 요일별 일반화, 현재 신호 또는 무정차 보장 검증이 아니다.** 지도 방향 대응 가정과 실제 휴대전화 현장 검증은 남아 있다. 기존 미확인 대기를 화면 시간에서 제외하는 한계도 이번에 전면 수정한 것은 아니다.

## API와 이후 자동화

- GitHub `collect` workflow를 수동 비활성화했다. 실행 중#33(run40727604374)도 completed/cancelled를 확인했다. API 키·기존 data 브랜치·과거 기록은 유지했다.
- API는 향후 이력 기준과 실제 관측의 차이 확인용이다. 차이가 사고·공사 때문인지 원인을 판단하려면 별도 사건 자료가 필요하다. 차이 감지 모니터를 이번에 배포한 것은 아니다.
- `.github/workflows/history.yml`:04:20 KST 신규 날짜 처리→검증→Release 업로드→메타데이터/앱용 패턴 커밋 절차를 준비했다. 이전 패턴을 보존하는 증분 갱신과 원본 재다운로드 방지 테스트를 포함했다.
- **작업 브랜치 파일만으로 예약 작업은 활성화되지 않는다.** 기본 브랜치 반영·실행 검증·Vercel Git 자동 배포 연결까지 확인하기 전에는 매일 자동 갱신 완료라고 하지 않는다. 이번 공개 갱신은 별도로 수행한다.
