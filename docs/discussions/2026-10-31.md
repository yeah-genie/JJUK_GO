# 2026-10-31 — 첨부 UI 5화면의 충실한 재현

## 사용자가 정한 작업 범위

- 첨부 `codex-clipboard-c4111d64-add1-4949-9d70-d482a58400f6.png`를 **유일한 visual source of truth**로 한다.
- 기존 쭉고를 조금 고치는 방식, 새 디자인 아이디어, 다크 테마, 대시보드, 과한 카드/아이콘/색/그라디언트/유리 효과를 금지한다.
- 기존 기능·데이터 로직은 유지하고 새 표현 계층에 넣는다. 운영은 바로 고치지 않는다.

- 390×844 실제 브라우저 렌더링의 스크린샷 5개를 원본과 직접 비교한 후 사용자에게 먼저 보여 준다. 운영 적용은 하지 않는다.

## 실제 작업

- 기존 작업 checkout에서 원격 최신 `ccr-94bac9df-i81579`의 `b9c6b03`까지 받아 새 브랜치 `codex/reference-ui-prototype`에서 진행했다. Claude의 최신 신호/경로·디자인 제안 작업을 되돌리지 않았다.
- `docs/prototype/reference-ui/`에 새로운 HTML/CSS/화면 어댑터를 만들었다. 기존 보이는 카드 HTML/CSS를 재활용하지 않았다. 기준 화면을 임의로 추가하지 않았다.
- `scripts/build_reference_ui.py`는 기존 엔진을 읽어 전용 엔트리만 생성한다. 운영 `docs/prototype/index.html`과 `src/`는 수정하지 않았다. 원본 빌더도 수정하지 않았다.
- 현재 운영 사이트에서 추출한 브랜드 색을 사용한다. 새 화면은 밝은 바탕, 진한 글자, 노란 주 CTA, 파란 지도 경로, 초록/빨강/회색 횡단이다.
- 시각 재현의 `sample=1`과 실제 데이터 모드를 분리했다. 샘플 숫자·경로를 실제 신호·GPS 기록으로 저장하거나 계산하지 않는다. 프로토타입 저장소 키도 운영 키와 분리했다.
- 다음 횡단 말풍선은 MapLibre 마커의 자식 요소다. 지도 이동·확대 시 해당 좌표와 함께 움직이며 꼬리가 마커 가장자리에 닿는다. 화면 가운데 고정한 별도 floating card가 아니다.
- 브라우저 비교에서 설정 하단 14px 잘림을 발견해 간격을 줄였다. 지도 확대 때문에 마커/현재 위치가 잘리는 것도 원본의 상대 배치와 지도 비율에 맞췄다.

## 한계와 다음 단계

- 이 작업은 이미지 우선의 별도 프로토타입이다. 원본 폰 하드웨어 테두리/노치/OS 상태바는 웹 UI로 만들지 않았다. 지리 배경과 글꼴 렌더링은 실제 지도/브라우저에 따라 원본 래스터 이미지와 차이가 있다.
- 새 급경사 토글의 독립 경로 제약은 기존 엔진에 없으므로 선호 저장과 미연결 안내만 한다. 기존의 급경사 지표를 포함한 경로 비교는 유지한다. 기능 완성으로 쓰지 않는다.
- 새 지도 레이어 선택 기능, 원본 외의 횡단 시간 지도 화면 재디자인, 실시간 신호 안내를 추가하지 않았다. 지도 entry의 실제 모드는 기존 로컬 지도 화면으로 연결한다.
- 새 밝은 이미지 저장 양식은 구현했으나 실제 기기 다운로드 QA는 남아 있다. 배포 가능한 통합 앱으로 단정하지 않는다.
- 이 다섯 화면을 사용자에게 먼저 보여 준다. 승인 없이 운영 엔트리 교체·기본 브랜치 병합·운영 배포하지 않는다.

사용자가 추가로 요청했다: BMAD 역할별 팀과 사용자 관점에서 개발, 새 디자인을 과하게 만들지 말고 데모 완성, 기존 Vercel 시작 로고 참고, 네이버 지도 연결, GitHub 실제 데이터 연동, 불필요 파일 정리와 준비되는 대로 업로드. 신호가 모두 미확인인 문제를 지적하고 아이콘 클릭 시 남은 초 등의 상세를 요청했다.

### 사용자 결정과 적용

- ‘조금 더 걸리더라도 편한 길’은 사용자 확정 방향이다. PM/UX가 제안한 별도 화면 없는 계획 미리보기는 구현 판단으로 채택했다. 길찾기 즉시 GPS를 기록하지 않고 기존 지도 화면 안의 ‘걷기 시작’에서 시작한다.
- BMAD PM/UX·설계/데이터·개발 역할이 검토했다. 역할별 근거는 TEAM_DIRECTION, DATA_INTEGRATION, NAVER_SETUP에 남긴다. 이후 통합은 Codex가 수행했다.
- 자동 학습 OFF의 속도 변경, 실제 출발 시각 초기화 누락, GPS 시작 위치 적용 누락, 지도 초기화/위치 마커 순서 문제를 새 표현 어댑터에서 고쳤다. 한국 신호 시각에는 kstSec()를 쓴다. 운영 알고리즘을 다시 쓰지 않았다.
- 첫 로고는 원래 SVG와 브랜드 폰트로 복원했다. 3.2초/건너뛰기. 원본 다섯 화면의 밝은 디자인과는 별개인 사용자 명시 예외다.
- 사용자에게 새 Maps 상품 등록·localhost/127.0.0.1/jjukgo 도메인 등록 위치를 안내했고, 실제 콘솔 수정 화면에서 이미 등록돼 있음을 확인했다. 등록/권한을 대신 변경하지 않았다. 받은 공개 Client ID는 로컬 .env.local에 두고 Git 제외했다. Client Secret은 받거나 사용하지 않았다.
- 실제 키로 네이버 지도·타일·경로·출처를 브라우저에서 확인했다. SDK 준비/부모 높이 0/리사이즈/최초 타일 로드/화면 전환 취소를 처리했다. 단순히 기존 지도 fallback만 되는 것을 연결 완료로 주장하지 않는다.
- 신호 모델은 개수용 xlist가 아닌 ID/방향이 있는 route.x를 사용한다. 기존 신뢰 기준을 통과한 예상 상태/잔여시간은 1초마다 갱신한다. 신호 버튼에 연결된 상세 창은 한 개이며, 기록 기간·신뢰 부족 이유를 보여 준다. 지도/마커 DOM 전체를 매초 갈아끼우지 않는다.
- 충분한 표본의 기록이 있으나 날짜 간 검증이 부족한 경우 ‘신호 기록 있음’과 ‘기록상 초록 구간(이력 추정)’을 보여 주되 현재 남은 시간이라고 쓰지 않는다. 저신뢰 현재 카운트다운과 ‘건널 수 있음’을 만들어 내지 않는다.

### 2026-10-31 저녁 최신 데이터 재확인

이전 새벽 보고(최근 timeout/404, 10/27까지 14일)는 그 시점의 스냅샷이다. 저녁에 원격을 다시 fetch한 결과 기본 브랜치가 67e7788, data 브랜치가 ea6bd8c로 갱신되어 있었다. 최신 호출 로그 09:42~10:02 UTC(18:42~19:02 KST)는 옛 API 성공을 약 5분 간격으로 기록했다. 새벽 오류가 계속된다고 단정했던 설명을 바로잡았다.

67e7788의 신호 manifest/시간대 조각만 작업 브랜치로 가져왔다: 10/14~10/30 17일, 패턴 후보 1734교차로. 기존 초기 작업 시점의 14일 자료로 고정하지 않는다. 단, 305초는 요청 간격이며 모든 교차로가 305초마다 성공 갱신됨을 뜻하지 않는다. 실시간 지도 설정은 꺼져 있고 검증된 실제 횡단 목록은 비어 있다.

기존 게이트를 그대로 검사했을 때 주말 18시 조각은 46방향이 통과했으나 확인 당시 19시 조각은 날짜 간 비교 기준을 통과한 방향이 없었다. 18시 실제 브라우저에서는 종묘입구의 예상 상태를, 19시 상세에서는 날짜 간 비교 자료 부족을 확인했다. 예시 숫자나 검증 전 이력을 현재 신호로 보이지 않게 구분한다.

최신 17일 자료로 실제 네이버 지도에서 종묘입구 서쪽 아이콘을 눌러 `신호 기록 있음 / 기록상 초록 구간 약 16초 (이력 추정) / 여러 날 비교 자료가 더 필요해요 / 10/14~10/30 · 실시간 아님`을 확인했다. 주변 신호도 자료가 있으면 열람할 수 있게 하되 검증 전 상태는 회색으로 유지한다. 홈 GPS는 기존 위치 요청·정확도 검사를 사용하도록 연결했고, 실제 야외 성공은 미검증이다. 요약 미니맵의 두 끝점 잘림을 수정하고 5개 브라우저 캡처를 재정리했다. 운영 배포·기본 브랜치 병합은 하지 않는다.

### 성신여대 데이터 범위·출발 도착 아이콘·사용자 분석

사용자는 종로를 벗어나 성신여대 쪽에서 신호가 전혀 보이지 않는다며 범위를 물었다. 출발·도착 아이콘을 다른 지도앱 참고로 넣고 사용자 불편/수요를 분석하도록 요청했다.

원격 기본 브랜치 67e7788이 여전히 최신 신호 이력임을 재확인했다. 현재 자료는 종로 한정이 아니다. 공개 역 좌표 반경 1km 기준 성신여대는 위치 8/이력 2/토요일 19시 이력 0, 혜화는 25/15/6, 강남은 52/49/16, 홍대는 36/2/2다. 구별 전체 통계나 검증된 물리적 횡단 수가 아니다. 위치 5174레코드와 이력 1734후보ID 중 위치 연결은 1723이다. 숫자 근거는 reports/reference-ui/audit-2026-10-31/coverage.json에 저장한다.

현재 시간 계획이 없는 주변 위치를 제외하던 조건을 풀고 회색 위치/시간 정보 없음으로 구분했다. 네이버 지도 idle 때 현재 중심 근처 위치를 최대 24방향까지 재선택하고 경로 연결 횡단은 따로 유지한다. 현재 시간 추정의 신뢰 gate는 완화하지 않았다. 출발은 파란 원점, 도착은 기존 노란색 깃발로, 각각 텍스트와 접근성 이름을 넣었다. GPS 현재 위치와 별개다. 카카오 공식 출발/도착 마커 샘플을 참고하되 타사 브랜드 이미지는 복사하지 않았다. 경로 횡단이 연결되지 않으면 다음 횡단이라고 주장하지 않고 횡단 정보로 표시한다. 신호 상세의 자동/수동 패닝 충돌로 왼쪽이 잘리던 문제도 브라우저로 재현해 수정했다.

Product Design audit 스킬로 홈→성신여대 검색→걷기 설정→경로 미리보기→신호 상세를 실제 캡처했다. 주요 다음 제안은 국내 장소·도보 출입구 검색, 초기 속도의 임시값 명시, 신호 대기 미포함 시간의 문구 구분, 우회 이익을 보며 고르는 흐름의 검증이다. 사용자 인터뷰 전 수요 가설과 실제 관찰을 구분했다. 자세한 보고서 REVIEW.md에는 각 단계 화면/상태/문제/제안과 미검증 사항을 남긴다. 이 제안을 모두 구현하거나 운영에 배포한 것으로 쓰지 않는다.
### 확인 가능한 신호 정보와 보행 부담 중심 후속

사용자가 ‘확실한 데이터 위주로 미확인 신호를 바꾸고 사용자 입장에서 고치라’고 승인했다. 현재 신호를 아는 것처럼 꾸미지 않고 과거 초록 지속시간/지도상 횡단 길이/시간 자료 없음으로 구별했다. 원본 시간대 JSON에서 최소 관측·시험 표본/적합도/정수 주기/창 범위를 통과하는 지속시간 기록을 별도 추출한다. 1729제어기 ID의 1.27MB 파일이며 현재 신호 검증 수가 아니다. 위상 ref/day0/xd를 내보내지 않아 과거 다른 시간대를 현재 카운트다운으로 대체하지 않는다. 성신여대 서쪽에서 과거 16초·10/25 04시 출처가 표시되는 것을 확인했다. 새벽 기록이 현재 신호라고 오인되지 않게 출처/설명을 유지한다.

사용자가 이어서 X가 창을 없애게 하고, 배리어프리 지향으로 급경사 등 불편한 길을 우회하되 긴 표의 가독성을 개선하라고 요청했다. 기존 Vercel 길음역→동덕여대 비교 이미지와 신호 상세 이미지를 참고했다. X는 네이버 정보창이 이벤트 전파를 막는 문제여서 실제 정보창 내부에 닫기 처리를 연결했고 브라우저에서 상세 제거를 확인했다. 닫힌 선택을 갱신 루프가 다시 띄우지 않는다.

계단·급경사·상승을 먼저 읽고 표는 펼치게 했다. 대안이 없으면 없는 열을 생략한다. 유효 대안이 있으면 편한 길/빠른 길을 선택하고 원시 지표를 함께 갱신한다. 급경사 덜 걷기 기본 ON: 기존 의미 있는 개선·우회/악화 제한을 그대로 통과한, 높이가 확인되는 후보를 급경사→상승→시간 순으로 우선한다. 계단 제외는 기존 조건을 사용한다. `f` 없음은 제작 파이프라인의 0값 압축일 수 있으므로 결측으로 오해하지 않고 노드 높이·육교/지하도 여부로 별도 판정한다. 신호 신뢰 gate·생산 알고리즘/엔트리는 변경하지 않았다.

검토 경로 길음역→동덕여대, 임시 검증 설정 4.8km/h·추가3분에서 편한 길 28분/급경사220m/상승39m/신호횡단3곳, 빠른 길27분/320m/43m/6곳을 확인했다. 선택을 바꾸면 지도와 지표도 바뀌고 계획 상태에서는 GPS를 시작하지 않는다. 검증 설정은 원래의 자동 맞춤·추가0.5분으로 복원했다. 최종 설정은 측정 전 큰 숫자 대신 자동 맞춤, 작은 임시 기준 설명이다.
