# 네이버지도·카카오맵과 비교한 사용자 입장 분석 (2026-10-31)

사용자 요청: "다른 네이버 카카오맵이랑 비교해서 알려줘. 다시 사용자입장에서 분석해봐."

**확인 방법과 한계**
- 두 앱을 직접 실행하지 못했다(이 작업 환경에는 휴대폰 앱이 없다).
- 기능 비교는 공개 기사·공식 페이지 검색(2026-10-31)으로 확인한 것과, 널리 알려진 일반 기능을 나눠 적었다.
- 쭉고는 지금 공개 화면(jjukgo.vercel.app)을 직접 실행해 본 결과다.
- 이 문서의 제안은 제안일 뿐이고, 사용자 승인 사항이 아니다.

## 2. 사용자가 실제로 느낄 차이

### 네이버·카카오가 확실히 나은 것 (사용자가 바로 비교하게 되는 것)
1. **검색:** 상호·주소·건물 출입구가 다 나온다. 쭉고는 오타를 받아 주지 않고, 서울 밖은 길찾기를 누른 뒤에야 안 된다고 한다. 사용자는 "검색부터 안 되네"로 첫인상을 정한다.
2. **위치와 방향:** 앱이라 화면이 꺼져도 위치를 계속 받는다(일반 기능). 나침반으로 내가 보는 방향을 돌려 보여 준다(일반 기능). 쭉고는 웹이라 화면이 꺼지면 GPS가 멈춘다. 방향 표시가 없고, 위치를 모를 때도 위쪽 화살표가 나온다.
3. **익숙함:** 버튼 위치, 출발·현재 위치 표시, 경로 다시 찾기를 이미 손이 기억한다. 쭉고의 지도 버튼(같은 기능 2개, 레이어 아이콘이 실제로는 '경로 전체 보기')은 처음 보는 사람이 헤맨다.
4. **대중교통 연결:** 걷다가 버스·지하철로 이어진다. 쭉고는 16.9km·4시간 42분 도보도 그대로 안내한다.
5. **믿음:** 큰 회사 앱의 숫자는 의심하지 않는다. 쭉고의 숫자는 처음 보는 서비스라 한 번만 틀려도 바로 신뢰를 잃는다.

### 쭉고만 줄 수 있는 것 (사용자가 "오?" 하는 지점)
1. **"지금 빨강 · 7초 뒤 초록불 (예상)":** 네이버·카카오 도보 화면에서는 볼 수 없는 정보다. 횡단보도 앞에서 "뛰어야 하나, 기다려야 하나"를 바로 정할 수 있다.
2. **"1분 더 걷고, 신호 대기 줄이는 길":** 큰 앱은 '가장 빠른 길'을 준다. 쭉고는 '덜 멈추는 길'을 준다. 출근길처럼 같은 길을 매일 걷는 사람에게 의미가 크다.
3. **내 걸음 속도로 계산:** 느리게 걷는 사람에게 "초록이 짧아요"를 알려 줄 수 있다.

### 쭉고의 약점이 더 크게 보이는 지점 (비교되기 때문에)
1. **초읽기가 안 나오는 신호가 많다:** 아침 출근 시간은 약 11%만 셀 수 있다. 나머지는 "남은 시간 모름"이다. 사용자는 핵심 기능을 기대하고 왔는데 대부분 '모름'을 보게 된다. 네이버·카카오에는 애초에 기대가 없으니 실망도 없다.
2. **실시간이 아니다:** 과거 패턴이라 실제 신호와 몇 초 어긋날 수 있다. 한 번 틀리면 "이거 안 맞네"로 끝난다. 큰 앱은 이런 위험을 지지 않는다.
3. **초읽기와 서두름:** 운전자용 남은 시간 표시는 신호 위반을 줄였다는 결과와, 서두르거나 급정거를 늘렸다는 결과가 함께 있다[4]. 보행자에게 "3초 뒤 빨간불"을 보여 주면 뛰는 사람이 생길 수 있다. 쭉고는 '뛰세요'라고 말하지 않지만, 숫자 자체가 재촉이 될 수 있다.
4. **웹앱의 한계:** 홈 화면 앱 설치, 백그라운드 위치, 알림을 쓸 수 없다. 걷는 동안 계속 화면을 켜고 봐야 한다. 네이버가 "화면 안 보고 걷기(음성 안내)"로 가는 방향과 반대다.
5. **서울만 된다:** 큰 앱과 달리 전국에서 쓸 수 없다.

## 3. 사용자 한 사람의 하루로 보면
- **출근(8:40), 집→역 1km:**
  - 네이버로 길은 이미 안다.
  - 쭉고를 열어 보니 신호 3곳 중 2곳이 "남은 시간 모름"이다. "굳이?"
  - 이 시간대 패턴 커버리지가 약점의 핵심이다.
- **점심(13:30), 회사 근처 식당:**
  - 신호 절반 이상에서 초읽기가 나온다.
  - "7초 뒤 초록불"을 보고 기다렸더니 맞는다. 쭉고가 가장 빛나는 장면이다.
- **처음 가는 곳:**
  - 검색과 출입구는 네이버가 낫다.
  - 쭉고는 "목적지는 네이버로 찾고, 횡단보도에서 쭉고를 본다" 정도의 보조 앱 위치가 현실적이다.

## 4. 그래서 제안 (승인 전)
1. **싸우지 말고 옆에 붙기:**
   - 검색·길안내 전체로 네이버를 이기기는 어렵다.
   - "신호 초읽기 + 덜 멈추는 길"에 집중하고, 첫 화면도 그 장면(지도 위 초읽기)을 먼저 보여 준다.
2. **'모름'을 줄이거나 숨기기:**
   - 초읽기가 되는 시간대·지역을 먼저 알려 준다. 예: "평일 낮 서울 ○○ 지역에서 잘 맞아요".
   - 모르는 신호는 조용히(작게) 보여 준다.
   - 실시간 API(10381) 승인이 이 약점을 푸는 열쇠다.
3. **서두름 방지:**
   - 남은 초가 건너는 데 필요한 시간보다 적으면 숫자 대신 "다음 신호를 기다려요"를 먼저 보여 준다.
   - 짧은 초를 크게 강조하지 않는다.
4. **비교에서 바로 보이는 기본기부터:**
   - 위치를 모를 때 화살표를 없앤다.
   - 아주 긴 경로에 경고를 준다.
   - '경로 종료'를 누르면 한 번 확인한다.
   - 출발 표시와 내 위치를 다르게 그린다.
   - 지도 버튼을 정리한다.
5. **스레드 데모:**
   - "네이버엔 없는 보행 신호 초읽기"를 평일 낮 커버리지가 좋은 경로로 찍는다.
   - '예상'이라는 말은 빼지 않는다.

## 5. 사용자 결정과 적용 (같은 날)
사용자: "ㅇㅋ 그걸 토대로 고쳐. 네이버나 카카오 같은 UI나 기능에 보행신호 남은시간 신호대기까지 따져 길고르기를 추가하는 느낌으로 가면 좋겠어."

방향: 지도 앱에 익숙한 사람이 바로 쓸 수 있는 형식(위 출발·도착 막대, 아래 경로 카드, 걷기 중 위 방향 카드·아래 남은 시간 막대)에 쭉고만의 두 가지(신호 초읽기, 신호 대기까지 따진 길 고르기)를 얹는다. 특정 앱의 화면·로고를 베끼지 않고, 색은 쭉고 기존 색(남색·노랑)을 쓴다. 로고는 그대로.

**결과 화면**
- 위: ← / 출발·도착(누르면 다시 고르기) / ⇅(바꿔서 다시 찾기)
- 아래 카드: 배지(덜 멈추는 길·계단 적은 길·덜 가파른 길·가장 빨리 걷는 길), **총 시간(걷기 + 예상 신호 대기)**, 거리·도착 시각, 🚦 "신호 대기 약 32초 · 신호 2곳(1곳 모름)", 걷기 시간·계단·오르막·급경사, 장단점 한 줄
- 5km 넘는 길: 카드에 "걷기엔 먼 길이에요. 대중교통과 함께 쓰는 걸 권해요", 안내 시작 때 한 번 더 확인
- '자세히' 표는 없앴다(예전 사용자 의견 "자세히 비교는 없애도 될듯"). 같은 정보가 카드에 있다.
- 조건 버튼, 안내 시작 버튼

**걷기 화면**
- 위 남색 방향 카드: "100m 후 횡단보도", "보행로를 따라 오른쪽으로" 등. 위치를 모를 땐 화살표 대신 '찾는 중' 아이콘과 "위치를 잡는 중이에요"
- 그 아래 신호 띠(300m 안, 패턴이 확인된 신호만): 색 원 + "3초 뒤 초록불" → 1초마다 줄어듦 → "15초 뒤 빨간불". 초록이 건너는 시간보다 짧으면 숫자 대신 **"다음 초록을 기다려요"**(서두름 방지)
- 아래 막대: 남은 시간(남은 신호 대기 예상 포함)·거리·도착 시각, 일시정지(둥근 버튼), 종료(누르면 확인)
- 지도 버튼은 2개(내 위치, 경로 전체 보기). 같은 기능 중복 버튼 삭제
- 출발 표시는 남색, 내 위치는 파란 점(구분)
- "GPS 연결 · 오차 약 10m" 같은 정상 알림은 띄우지 않음(문제일 때만)
- 신호 패턴이 없는 횡단: "신호 시간은 몰라요. 현장 신호를 확인하세요"

**확인**: 390×844·360×640, 화 14:10 고정, 성수역→서울숲(초읽기 3→1→"15초 뒤 빨간불" 전환 확인)·혜화역→낙산공원(대안 2개 카드, 모르는 신호 문구). 페이지 오류 없음.
**확인 못 함**: '다음 초록을 기다려요'가 실제로 뜨는 장면(조건이 맞는 신호를 시험 시각에 못 만남, 코드로만 확인), 네이버 지도 위 모양(작업 환경에서 네이버 지도가 뜨지 않음), 걷는 중 지도가 내 위치를 따라가는 기능(아직 없음).
