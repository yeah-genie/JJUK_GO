- TData 키나 추가 API를 호출하지 않고 GitHub Actions, `data` 브랜치 로그, 압축 segment 실제 시각을 확인했다. 20:24 KST 기준 현재 정상 회복, 19:02~20:23 성공17회(중앙306초). 그러나 14:40:56~19:02:21 성공 공백4시간21분25초가 있었고, 그 사이 TimeoutError와429가 반복됐다.
- 핵심10개 교차로+서울 탐색 교대는 이론상 한 핵심 교차로당 약101분40초 순회. ‘모든 신호를5분마다 계속 모음’이 아니다. 수집 로그/최신 실제 데이터 시각/방향별 관측 공백을 구분해야 한다. 수집 코드·workflow·설정은 이번에 변경하지 않았다.
- 서울시 OA-21207: 계단도로 구분 `SE_CD=2`, 공간파일+passWeak API, 공공누리1. 실제 파일 내부·API 호출은 미검증. 경사는 국토지리정보원 공개DEM 원자료 제공경로15059920 확인, 로그인과 대용량 다운로더 필요. 서울 도엽 해상도/데이터 획득은 미검증.

## Walking 1차 데모와 GPS

- 사용자: 먼저1차 데모를 내야 써볼 수 있고, 논의한 걷기 버전까지 구현하는 것이 우선 목표라고 밝혔다. 이어 사용자 GPS가 구현 가능한지, 앱이 필요한지 질문했다.
- 응답 방향: 모바일웹에서도 사용자 허용 후 현재위치·위치갱신이 가능하다. 첫데모는 HTTPS웹GPS로 진행하고, 권한거절/정확도저하/갱신중단 시 지도선택·상태안내를 제공한다. 화면잠금·백그라운드 상시추적은 웹보장이 어렵고 앱전환 검토 범위다. GPS만으로 실시간신호나 횡단안전을 보장하지 않는다.
- `docs/FIRST_DEMO_PLAN.md`에 전체 흐름, 신호·계단·경사·비교·GPS·HTTPS공유·피드백 완료조건과5단계 구현순서를 작성했다. 경사 데이터 미확보 상태를 완료로 부르지 않는다. 세부 실행안은 에이전트 제안이다.
- 첫작업으로 수집기의 짧은 네트워크 재시도와 실패대상 순환정지 문제를 수정했다. 전체59개 테스트 통과(3.36초), 실서비스API는 호출하지 않았다. 처음 샌드박스 기본 임시폴더 생성오류가 나서 작업폴더 내 `.pytest_cache/collector-fix-20261028`을 basetemp로 지정해 재실행했다.
- 운영 수집 기본브랜치는 아직 미변경이다. GPS·계단·경사 새기능은 아직 미구현이며, 계획 작성·수집기 수정만으로 Walking 데모를 완료했다고 주장하지 않는다.

- OSM 검출 계단 구간/길이와 Mapzen/AWS 공개 지형 타일33장의 약120m 파생망을 연결. 국토지리정보원 DEM과 서울시 계단 공간파일 통합은 아니다. 약120m는 파생망 간격으로 실제 고도 정확도를 뜻하지 않는다.
- +1/+2/+3분 예산 안에서 세 가중치 후보를 비교한다. 비용계수는 검증된 피로 점수가 아니며 전역 최적·무장애 보장 없음. 모르는 신호 대기는 예산검사에서45초 가정, 화면 시각에서는 제외된다는 한계를 기록한다.
- Vercel 플러그인 연결 후 프로젝트 목록 조회 성공. 첫 생성 요청은 요청 본문 전달형식을 수정했고, 정정 요청은 팀 쓰기권한403으로 거절됨. 도구 안내대로 팀 승인 링크 발급. 사용자가 ‘expired 됐대 한번만 다시’라고 하여 새 링크를 발급했다. 인증 링크는 저장소에 남기지 않는다. 기존 Vercel 프로젝트는 수정하지 않았다.
- 검증과 화면 근거, 남은 작업은 `WALKING_DEMO.md`. Vercel 공개 배포 및 실제 휴대전화 야외 보행까지 완료로 쓰지 않는다.
