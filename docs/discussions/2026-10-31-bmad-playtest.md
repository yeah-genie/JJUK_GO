# BMAD 3인 새 화면 체험과 토론 (2026-10-31)

사용자 요청: "bmad랑 저거 직접 체험해보면서 뭘 고쳐야할지 토론해봐. 그리고 논의한 내용 토대로 고쳐."

대상: 지금 공개 화면(`/reference-ui/`, 지피티가 만든 새 UI)과 그 아래 길찾기 엔진.
참여: UX 디자이너(Sally), PM(John), QA(Quinn) 에이전트. 각자 Playwright로 390×844·360×640 화면을 직접 눌러 보고, 가짜 GPS로 걸어 보고, 코드를 읽었다. 공개 사이트에서는 네이버 지도가 정상으로 떴다(QA 확인). 로컬에서는 지도 타일이 막혀 기본 지도로 대신 봤다.

**고치는 기준(동결 규칙 유지):** 쓰는 데 막히거나, 잘못 읽히거나, 신뢰를 깨는 것만 지금 고친다. 모양(디자인)은 지피티 담당이라 바꾸지 않는다. 문구·숫자·동작만 고친다.

## 2. 의견이 갈린 것
- **주변 신호를 아예 숨길까, 흐리게 둘까.** UX는 "계획 화면에선 반경 60m로 줄이거나 흐리게", PM은 "계획 화면에선 숨기기". → **결정: 계획 화면에서는 경로 위 신호만 보인다.** 걷는 중에는 지금 보는 곳 근처(150m, 최대 8개)만 흐리게 보인다. 주변 신호는 '어느 길이 나은지'에 답하지 않고, 계획 화면의 질문은 그것이기 때문.
- **신호 창은 '지금' 기준인가 '도착할 때' 기준인가.** 경로 위 신호는 **도착할 때 기준**으로 바꾼다(계획 화면은 지금 출발 기준, 걷는 중에는 내 위치에서 남은 거리 기준). 경로 밖 주변 신호는 도착 시각을 모르니 지금 기준 그대로 두고 '(예상)'을 붙인다.
- **'편한 길' 이름.** 급경사가 오히려 늘어나는 대안(혜화)에서 '편한'이 맞는지 PM이 물었다. 이름은 화면 설계(지피티 몫)라 이번에는 바꾸지 않고, 아래 단점 칩·문장이 이미 단점을 말하는지만 확인했다(말하고 있음).

위 1~18을 모두 고친다. 모양은 그대로 두고, 버튼을 새로 넣어야 하는 곳(9 다시 찾기, 16 조건, 17 다시 고르기)은 기존 버튼 모양을 그대로 쓴다.

## 4. 미룬 것 (나중)
- 뒤로가기(브라우저·안드로이드)가 앱 밖으로 나감, 걷는 중 새로고침하면 기록이 사라짐
- 일시정지 시간이 총 소요 시간에 들어감
- 30초 넘게 GPS가 끊겨도 화면에 계속 보이는 상태 줄이 없음(알림만)
- 공유 링크의 출발·도착이 닫은 뒤에도 주소에 남음
- 검색: Enter 무반응, '장소' 탭 필터, 처음 열 때 "검색 결과가 없어요", 오타 제안, 서울 밖 장소 즉시 안내
- 360×640에서 지도 버튼과 위 카드 겹침, 지도 아이콘 스크린리더 이름 "Map marker", 출발 표시와 현재 위치가 같은 파란 원
- 29km 같은 아주 긴 경로 경고
- 걷는 중 속도가 낮게 나옴(가짜 GPS 방식 탓일 수 있어 실기기 확인 필요)
- 광화문 "지도상 횡단 약 5m" 자료 의심

## 5. 확인하지 못한 것
- 로컬에는 지금 시각에 믿을 수 있는 신호 패턴이 적어, 남은 초 카운트다운은 고정 시각(화 14:10)에서만 봤다.
- 네이버 지도 위 신호 창 위치는 공개 사이트에서만 볼 수 있다(로컬은 기본 지도).
- 실제 휴대폰 키보드·음성 안내·이미지 저장은 확인 못 했다.
