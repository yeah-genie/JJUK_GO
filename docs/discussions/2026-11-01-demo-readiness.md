# 데모 공개 전 점검 회의 (BMAD PM·UX·QA, 2026-11-01)

사용자 요청: "ㅇㅋ 그럼 그동안 bmad 에이전트들이랑 데모버전을 내려면 어디를 개선해야될지 논의해서 깃허브에 올려"

참여와 방법:
- PM(John): 문서·운영 API를 확인했다.
- UX(Sally): 스레드 앱 안 브라우저처럼 꾸며(UA) 휴대폰 크기 390×664로 처음 방문자 흐름을 봤다. 시각은 화 14:10 고정과 실제 지금(일요일 새벽 3시) 두 가지.
- QA: 점검 스크립트 7종과 pytest를 돌리고, 운영 사이트를 끝까지 돌렸다. 예외 상황, 느린 3G, 개인정보도 봤다.
- 이 작업 환경에서는 네이버 지도가 뜨지 않아 모두 대체 지도로 봤다(실제 휴대폰 확인 필요).

이 문서의 고칠 목록은 회의 제안이다. 사용자 승인 전에는 구현하지 않는다.

## 1. 판정
- **QA: 데모를 막는 문제는 없다.**
  - 검사 7종과 pytest 83개를 통과했다. 운영 사이트 JS 오류 0건.
  - 홈 준비 0.7초, 성수→서울숲 길찾기 1.2초.
  - 사용 기록에 좌표·장소 이름이 없다.
- **PM: 조건부로 공개해도 된다.**
  - 평일 13~15시에 올린다.
  - 아래 '꼭 고칠 것'을 고친다.
  - "실시간 신호"라고 쓰지 않는다.
  - 밤·아침에 들어온 사람은 신호가 거의 회색이라 "네이버 지도 흉내"로 끝날 위험이 있다.
- **UX:** 지도 앱 흐름은 익숙하고 경로 카드는 정직하다. 처음 10초 안에 **숫자가 무슨 뜻인지, 실시간이 아니라는 것**이 전달되지 않는다.

## 3. 고치면 좋은 것
- 스플래시 3.2초가 길다. 1.5초로 줄이고 핵심 가치를 한 줄 넣는다("신호 대기까지 계산한 도보 길") (UX)
- 위치가 없을 때 시청이 나오는 이유를 표시한다: "예시 위치: 시청 · 내 위치 켜기" (UX)
- 안내 중 신호 말풍선이 화면 오른쪽에서 잘린다 (QA)
- 첫 이용 데이터가 많다: 약 20.6MB(압축 해제), 타일 b41 2.17MB. signal-hours를 두 번씩 받고, 큰 정적 자료가 `max-age=0`이다 → 메모리 재사용, 버전 이름 + 오래 캐시 (QA)
- 지하철 API의 역 이름 값 검사(한글·숫자만, 길이 제한). 지금도 화면에서 이스케이프해서 XSS는 아니다 (QA)
- 6시간 넘는 경로는 안내 시작 버튼을 약하게 (QA)
- "내 속도 걸으면 재요" → "걸으면서 속도를 맞춰요" (UX)

## 4. 데모에서 숨길 것
- 버스: 정류소정보조회 승인 전. 화면에 입구가 없다. `/api/transit-status`는 키만 보고 `bus:true`를 돌려주니 승인 전까지 화면에 연결하지 않는다.
- 지하철 '이번/다음 열차' 판단: 2번 표의 7번 확인 전까지.
- 녹화에서 뺄 것: 걸음 공유 카드, 아스팔트 테마, 크게 돌아가는 역 출발 경로(수색·구로 등).

## 5. 스레드 글 (PM 제안)
**보여 줄 것** (평일 14시 전후, 녹화 숫자 = 그 시각 앱 화면 숫자)
1. 20초 영상: 지도 홈에서 신호 숫자가 줄어든다 → 검색 → "덜 부담스러운 길" 카드
2. 덜 부담스러운 길과 빠른 길 카드가 **둘 다 나오는 경로**. 성수역→서울숲은 지금 카드가 하나라(UX 확인) 다른 경로를 고른다. 녹화 직전에 숫자를 다시 확인한다.
3. 더 나은 길이 없으면 억지로 추천하지 않는 화면(광화문→시청역): 신뢰를 주는 장면
4. 마지막 글: 링크 + "평일 낮에 가장 잘 보여요 · 아직 만드는 중이에요"

- **말해도 되는 것:** "과거 신호 기록으로 계산한 예상", "계단·급경사·신호 대기를 같이 세요"
- **말하면 안 되는 것:**
  - "실시간 신호", "정확한", "안전한 길", "무장애", "보장", "뛰세요"
  - 네이버·카카오보다 낫다는 비교
  - "직접 걸어 보니"(현장 시험을 안 했다)
  - 버스 기능이 있다는 말

## 6. 올린 뒤 볼 숫자 (PM)
- 방문 → 경로 검색 비율, 앱 안 브라우저에서 위치 실패 비율
- 대안 길이 나온 비율, "덜 부담스러운 길"을 고른 비율
- 걷기 시작 / 경로 선택
- 검색 시각 분포(신호 자료가 적은 시간 비율)
- "실시간이에요?" 같은 댓글 수(많으면 2번 문구를 고친다)
- 검색이 20~30회 미만이면 비율은 참고만 한다. 11/12 신호 재측정 결과와 함께 본다.
