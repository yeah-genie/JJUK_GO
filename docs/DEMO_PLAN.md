# 스레드 데모 계획 (2026-10-30)

입력: BMAD PM 에이전트 의견, 실제 앱 결과(평일 시각 고정), 사용자 결정(신호 중심 개편, '건널 수 있어요' 허용, 지도는 패턴 예상).

## 형식
- 20~30초 화면 녹화 1개 + 글 3개 스레드.
  1. 영상 + 한 줄: "비슷한 시간이면 신호 앞에서 덜 서 있는 길"
  2. 경로 비교 카드 2장(숫자는 녹화 직전 앱 화면 그대로)
  3. '대안 없음' 사례 + 링크(https://jjukgo.vercel.app)
- **찍는 시간: 평일 오후 1~3시.** 지금 기록(10/14~10/27)으로 신호 패턴이 확인된 교차로가 가장 많은 시간(약 53%). 아침 8~9시는 약 11%라 아이콘이 대부분 회색.

## 경로 (평일 14:10 기준 실제 결과)
| 순서 | 경로 | 보여 줄 것 |
|---|---|---|
| ① | **성수역 → 서울숲** | 쭉고 길 35분 · 신호 횡단 2곳 · 예상 신호대기 0초 vs 빠른 길 34분 · 5곳 · 1분 11초(4곳 모두 패턴 확인). "1분 더 걷고 신호 앞에서 1분 넘게 덜 서 있어요". 지도 신호 아이콘·'다음 횡단보도' 말풍선 |
| ② | **미아사거리역 → 청운답원(북서울꿈의숲)** | +1분으로 신호 횡단 1곳·급경사 290m·오르막 23m↓ (경사 쪽 가치). 검색어는 반드시 '청운답원' |
| ③ | **광화문 → 시청역** | 대안 없음 + "도착하면 약 87초 기다릴 것으로 예상돼요". 억지로 추천하지 않는다는 신뢰 |

## 올리기 전에 꼭 참이어야 할 것
1. 녹화한 숫자 = 그 시각 앱 화면 숫자(시간대마다 다르다).
2. 지도 아이콘·말풍선은 **과거 기록 패턴 예상**이라고 보인다(범례 '패턴 예상 10/14~10/27', '(예상)'). **실시간이라고 말하지 않는다** — 실시간 API는 승인 전(OFF).
3. 처음 접속(시크릿 창)에서 오류 없이 검색 → 비교 → 걷기 시작까지.
4. 익명 이벤트 3종이 Redis에 쌓인다(2026-10-30 확인).

## 글에 쓰지 않을 것
- "실시간 신호", "정확한 신호", "안전한 길", 네이버·구글보다 낫다는 비교.
- "걸어 보니" (현장 확인 안 함) → "데이터 기준".

## 올린 뒤 볼 것
- route_search 수, 대안 비율(예상 약 30%), selected_route 중 쭉고 길 비율(핵심), walking_started/selected_route.
- 20~30회 미만이면 비율은 참고만. 댓글의 '신호' 질문 수.

## 알려진 문제(데모 경로는 피함)
- 역에서 출발하는 일부 경로가 크게 돌아감(수색·구로·불암산역, 외부 보행 엔진보다 1.3~1.6배). 역 연결 통로 누락 추정 → `docs/QA_AUTOMATION.md`.
- 신호 패턴 확인 비율이 시간대에 따라 크게 다름(기록 14일치). 11/12 재측정.
