# 모바일 사용성 점검과 수정 (2026-10-30)

입력: 사용자가 전달한 외부 점검(GPT, 공개 앱 390×844) + BMAD 더블체크(UX 디자이너·아키텍트 에이전트, 코드와 390×844 Playwright로 재현).
범위: 브라우저 390×844·360×640. **실제 휴대폰의 키보드·브라우저 하단 막대·터치/드래그·야외 가독성·현장 GPS는 확인하지 못했다(미검증).**
전후 화면: `reports/ux/2026-10-30/`(왼쪽 전, 오른쪽 후. 평일 08:40 고정, 혜화역→낙산공원).

## 1. 관찰 재현 결과
| 관찰 | 재현 | 원인(코드) |
|---|---|---|
| A. 출발지 화면에 도착지가 안 보임 | 재현됨 | 안내가 "출발지를 골라요" 한 줄뿐 |
| A. 거리 기준 설명 없음 | 재현됨 | 출발지가 없으면 **지도 기준점 서울광장**에서 잰 거리였다(설명 없음). 출발지 화면에서는 도착지 기준 |
| A. 도착지가 최근 목록 맨 위에 0m | 재현됨 | 최근 목록에서 반대쪽 장소를 빼지 않음 |
| B. 탭 전환·상세 복귀 때 자세히 비교가 접힘 | 재현됨 | 다시 그릴 때마다 `setBasisOpen(false)` |
| B. 표를 내리면 열 머리글이 사라짐 | 재현됨 | 머리글 고정 없음 |
| C. "계단 없이 더 편하게 걸어요" 과장, 단점은 회색 한 줄 | 재현됨 | 같은 화면에 급경사 증가 |
| C. "약 2분 1초" | 재현됨 | 초 단위 그대로 |
| C. 빠른 길 "가장 빨리 가는 길" | 재현됨 | 시간은 신호 대기 제외인데 '도착'으로 읽힘 |
| D. 조건 조정이 전체 설정으로 | 재현됨 | 학습 설정이 먼저, 이동 조건은 세 번째 |
| E. 비교표 신호 횡단 1곳 vs 상세 2곳 | 재현됨(**불일치**) | 비교표는 서울시 횡단보도 자료(보행등), 상세는 그래프 신호 노드 — 출처가 달랐다 |
| E. 홈 횡단 시간 패널이 큼, 내 걸음 입구 중복 | 재현됨 | 패널 약 140px, 기본 켜짐 |

## 2. 고친 것과 줄어든 불편
| 불편 | 전 | 후 |
|---|---|---|
| 지금 무엇을 고르는지 기억해야 함 | "출발지를 골라요" | 검색 화면 위에 **출발: 고르는 중 / 도착: 낙산공원** 두 줄(누르면 그쪽을 고름). 입력칸도 "출발지: …" |
| 거리 숫자의 기준을 모름 | 기준 없는 3.1km(서울광장 기준) | "거리: 도착지 낙산공원까지 직선" 등 실제 기준을 쓰고, **기준이 없으면 거리를 숨김** |
| 출발지 후보에 도착지가 0m | 맨 위에 낙산공원 0m | 반대쪽에서 고른 곳은 최근 목록에서 뺌 |
| 결과 없음에서 막힘 | 공개 검색만 | + "지도에서 직접 고르기" |
| 두 길을 번갈아 볼 때마다 상세를 다시 엶 | 탭 누르면 접힘 | 탭 전환·횡단 목록 복귀 때 **펼침·스크롤 유지**, 지도는 움직이지 않고 강조만 바뀜 |
| 표를 내리면 어느 열인지 모름 | 머리글 사라짐 | 머리글 고정(sticky) |
| 추천 이유만 보이고 손해는 묻힘 | "계단 없이 더 편하게 걸어요" + 회색 한 줄 | 배지 "확인된 계단을 피해요", 제목 "확인된 계단 1구간을 피하는 길", **같은 크기 칩**: ＋확인된 계단 1구간 적어요 / －약 2분 더 걸어요 / －급경사 50m 많아요 |
| 빠른 길의 장단점이 안 보임 | "쭉고 길보다 약 2분 1초 빨라요" | "걷는 시간이 가장 짧은 길" + ＋약 2분 덜 걸어요 / ＋급경사 50m 적어요 / －확인된 계단 1구간 많아요 |
| 시간 오해 | "가장 빨리 가는 길", "2분 1초" | "시간은 걷는 시간만이에요 · 신호 대기 제외", 1분 넘으면 30초 단위 반올림 |
| '계단 0'의 뜻 | "계단 0구간" | 표 이름 "확인된 계단" + "계단은 지도에 표시된 곳만 세요" |
| 조건 하나 바꾸려고 설정 전체로 | 학습 설정부터 | 결과 화면 안 **조건 패널**: 확인된 계단 피하기, 더 걸어도 되는 시간 1/2/3분, 적용 중인 걷는 속도 → "이 조건으로 다시 찾기"(찾는 동안 적용된 조건 표시, 저장 실패도 알림) |
| 횡단 개수가 서로 다름 | 1곳 vs 2곳 | 상세 목록을 비교표와 **같은 기준**으로, 제목에 어느 길인지, "신호 횡단 N곳 · 그 밖의 횡단 M곳", 비교표의 신호 횡단 줄에서 바로 열림 |
| 긴 설명을 지나야 상세 | 설명 5문단 뒤에 링크 | 링크·핵심 한계 한 줄을 먼저, 긴 설명은 "데이터 기준"으로 접음(숨기지 않음) |
| 홈에서 할 일이 흩어짐 | 횡단 시간 패널 기본 켜짐, 내 걸음 입구 둘 | 검색이 중심, 횡단 시간 지도는 버튼으로 켜는 모드, 내 걸음은 설정 하나로 |
| GPS 단계가 많음 | 도착지 → 출발지 화면 → 내 위치 → 권한 → 대기 → 결과 | 위치 권한이 이미 있으면 **홈을 열 때 내 위치가 출발지**, 도착지만 고르면 바로 비교. ⊕ 버튼도 출발지가 비어 있으면 출발지로. 권한을 묻기 전에는 앱을 열자마자 묻지 않음 |
| 매번 로고 3.2초 | 매번 | 첫 방문만 |
| 걷기 버튼 차이를 모름 | 그만 걷기 / 걷기 끝내기 | 경로로 돌아가기 / 걷기 끝내고 기록 보기 |
| 펼치면 지도가 거의 안 보임 | 시트 74% | 66%, 나머지는 시트 안 스크롤 |

시험: `scripts/check_screens.cjs`(390×844·360×640)에 탭 전환 뒤 펼침 유지, 횡단 목록 복귀 뒤 펼침 유지, 열 머리글 보임, 횡단 목록=비교표 신호 횡단, 장단점 칩, '편하' 단정 금지, 조건 패널 취소·적용을 넣었다.

## 4. 아직 확인 못 한 것(미검증)
- 실제 휴대폰 키보드가 검색 결과·버튼을 가리는지, 브라우저 하단 막대와 겹치는지

- 현장 GPS 정확도와 보행 경로 정확성
