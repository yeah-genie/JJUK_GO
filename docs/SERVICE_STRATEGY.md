# 쭉고 서비스 전략: 그늘로 벤치마킹 토론 결과

2026-10-29 · BMAD 팀 2차 회의(Mary·John·Sally·Winston 토론, 진행 Claude). 입장 문서: `reports/team-2026-10-29/16_Mary_service_position.md`, `16_John_service_position.md`, `16_Winston_service_position.md`, `16_Sally_benchmark_debate.md`. 안건: `15_meeting2_brief.md`.

이 문서의 판정·기준은 **팀 제안**이며 사용자가 승인한 것이 아니다. 그늘로 서술은 Mary 12번 보고서(앱 미설치, 사이트·스토어·홍보 이미지·보도 기준)에 의존하며 앱 내부 동작은 확인하지 못했다.

## 1. 그늘로는 왜 되는가 (재현 가능 / 불가)

| 요인 | 재현 | 쭉고에서 |
|---|---|---|
| 약속 문장 안에 켜는 순간("추운 날엔 / 더운 날엔") | 가능 | 현 한 줄에는 순간이 없다. 켜는 순간(출발 전 계획)은 가설 |
| 전 지역에서 계산되는 값이 첫 화면부터 보임(해·건물·가로수) | **불가(현재)** | 핵심 숫자가 gate로 닫힘. 약속과 즉시 값이 분리됨 |
| 단일 컨셉이라 확장해도 유지 | 가능 | "서두르지 않아도 되는 길"이 같은 역할 가능, 단 훅으로는 약함 |
| 몸이 먼저 느끼는 보편 불편(더위) | 부분 | 신호 앞 초조함은 폰을 켜게 하는 순간이 아님(추정) |
| 폭염·보도·방송·토스 등 외부 사건 | **불가** | 대응 트리거 없음. 같은 확산 속도를 계획 전제로 삼지 않음 |
| 1인·무가입·가벼운 운영 | 가능 | 정적 웹 구조가 오히려 더 가벼움. 지킬 강점 |

## 2. 팀의 합의

1. **그늘로와는 "같은 자리(출발 전 도보 길 비교)에 놓인 다른 문제"**다. 변수가 다르다(열·경사·계단 ↔ 신호 시간 대비 내 걸음). 보완 관계는 가설이다.
2. **방어력은 약하다.** 쭉고의 데이터는 공개 자료이고 그늘로는 주 1회 출시하며 횡단보도 위치를 이미 표시한다. 쭉고가 지킬 수 있는 자리는 기능이 아니라 숫자마다 확인/추정/모름을 붙이는 규율이다. 이것을 "우리가 더 낫다"로 말하지 않는다.
3. **그늘로가 이미 하는 것(계단·경사·허용 우회·두 후보 비교·횡단보도 개수 표시)은 차별점이라 주장하지 않는다.** 소개 문구에서 "그늘로와 다르다·못 한다·최초"를 쓰지 않는다.
4. **가져올 것:** 약속 문장에 켜는 순간 넣기, 후보 카드 두 장을 같은 칩 구성으로, 설정 한 번 후 입력 감소, 짧은 해요체와 "앱보다 현장 우선" 한 줄, 무가입. **피할 것:** 기능 확산(대중교통·러닝·방범), 환경 레이어·색 복제, 근거 없는 퍼센트, 약자·사망 통계로 절박함 만들기, 외부 사건에 기댄 성장 가정.
5. **쭉고의 틀림은 위험의 방향이 다르다.** 그늘로의 틀림은 "덜 좋은 길"이고, 쭉고의 틀림은 "못 건너는 길이 건널 만하다고 보임"이다. 그래서 숫자 개방은 횡단 단위 증거와 재폐쇄 경로가 있을 때만 한다(Winston).

## 3. 목표의 현실성 판정 (제안)

| 질문 | 판정 | 핵심 근거 |
|---|---|---|
| 서비스를 숫자 닫힘 상태(MVP-0)로 완성 | 현실적 | 사용자 작업 없이 에이전트가 끝낼 수 있음 |
| "초록불 안에 건널 수 있는지 숫자로"(약속 이행) | **조건부, 현재 조건을 채울 경로가 불투명** | 방향 대응·점멸 의미가 미확인이고 현장 불가. 길이 통계 시도도 방향을 가리지 못함(`17_crosswalk_direction_check.md`) |
| 그늘로만큼 즉각 이해되는가 | 아니다(모름에 가까움) | 부정형·결과 상태 문장이고 순간이 없음. 수요 조사 0건 |
| 첫 화면 가치 | 현재 약함 | `횡단 N곳 · 이력 · 모름`은 수량이지 차이가 아님(Sally 자기 정정) |
| 일반인 공감 + 약자 더 큰 공감 | 구조는 가능, **증거 0** | 그늘로 구조는 재현 가능하나 판정할 수단(인터뷰)이 없음 |
| 1인 유지 | 조건부 | 구조는 맞음. 신호 이력이 단일 외부 의존이고 2026-11-15 이후 신규 수집이 불확실 |

**한 줄 판정:** 목표는 "조건부 현실적"이다. 조건은 단 하나, **숫자를 열 수 있는 근거가 생기는 것**이다. 그 전까지 쭉고는 그늘로와 첫 5초 격차가 구조적으로 크다.

## 4. 팀 내 쟁점과 정리

| 쟁점 | 정리 |
|---|---|
| Sally의 `횡단 N곳` 칩은 첫 가치인가 (John·Mary·Winston 반박) | 아니다. 그늘로도 횡단 개수를 표시하고, 차이를 만들지 않으며, 횡단 단위 이력은 방향 키(맞는 곳 35.9%)에 걸려 있다. **교차로 단위** 표기("이 교차로: 신호 이력 있음")만 쓴다 |
| Winston의 "검증 구역만 개방"은 구역이 0일 수 있다 (Mary) | 인정. 구역이 0이면 그늘로 대비 비대칭은 영구히 남는다 |
| John의 반증 기준(5명 보행·현장)은 판정 불가 (Winston) | 인정. 기준을 `셀별 일치율·명세 답·원격 길이 표본·개방 후 제보 1건이면 재폐쇄`로 바꾼다 |
| 공개 규칙 충돌 (John) | MVP_PLAN §9("닫혀 있으면 '준비 중'과 함께 공개")와 "숫자 닫힌 채 공개 금지"는 양립 불가. 최신 사용자 발언을 따르면 숫자가 열리기 전 앱 공개는 없다 |

## 5. 알리는 법 (Threads에는 완성된 조각만)

- 그늘로의 개발자 SNS 운영 방식은 **모른다**. "그늘로가 이렇게 퍼졌다"를 근거로 한 발행 계획은 만들지 않는다. 배울 것은 두 가지: 한 장면이 곧 제품, 사용 상황 피드백을 수집해 제품을 바꾼다.
- 완성된 조각의 정의(John 제안): ① `준비 중·측정 전`이 한 화면에도 없이 단독으로 끝난다 ② 실데이터이고 확인/추정/모름이 이미지 안에서 읽힌다 ③ 재현 가능하다 ④ 근거보다 큰 주장을 하지 않는다.
- 현재 후보: 횡단 길이 공공자료 분석(서울 25개 구 11,562개, 중앙값 19.5m)처럼 **단독으로 끝나는 분석 결과**. 단 이것이 "완성된 것"인지, 프로필 앱 링크를 걸지는 사용자가 정한다. 조각은 신뢰 자산이지 사용 이유가 아니고, 숫자가 열리기 전까지 시간을 버는 수단이다.

## 6. 중단·전환 기준 (제안, 날짜는 사용자 결정)

- 숫자를 열 경로(공식 명세 답·길이 자료·제보) 중 어느 것도 사용자가 정한 날짜까지 열리지 않으면 숫자 약속을 접고 "정직하게 모름을 보여 주는 지도·계산 기준 도구"로 전환할지 사용자가 결정한다.
- "여유 있음"이라고 표시했으나 못 건넌 사례가 1건이라도 확인되면 그 횡단 숫자를 다시 닫는다.
- 그늘로가 횡단 신호 시간·건너는 시간을 제공하는 것이 확인되면 차별 후보를 재판정한다(아직 아무도 앱을 설치해 확인하지 않음).
- 2026-11-15 이후 신호 데이터가 갱신되지 않으면 14일 이력을 기준일이 붙은 동결 기준선으로 쓰고 만료 규칙으로 '모름'으로 떨어뜨린다.

## 7. 지표 (제안, 임계값 없음)

조회·좋아요·다운로드·팔로워는 수요가 아니다. 쓸 수 있는 것: 구체적 사용 상황(장소·상황을 적은) 회신 수, `준비 중/정보 없음`을 안전·확정으로 오해한 사례 수, 숫자가 나오는 횡단 비율, "여유 있음" 오표시 건수(개방 후). 기준선은 기존 Threads 게시물 1건(약 1만 조회, 좋아요 57, 댓글 26, 구체적 사용 상황 1건)뿐이다.

## 8. 팀이 내린 권고 (제안)

1. **지금 바로 진행(사용자 결정 불필요):** 홈·결과의 신호 이력 표시를 교차로 단위로 교체, gate 평가 함수와 횡단별 재폐쇄 플래그, 평일/주말 불일치 '모름', 신호 패턴 기준일과 만료 규칙, OA-21209를 그래프 횡단과 매칭해 **길이 입력을 공공자료로 교체**(합격 기준을 결과 보기 전에 정한다), 11/15 전에 14일 이력 원본과 기준일을 확정.
2. **사용자 부담이 작은 것 하나:** T-Data 문의 1건(10381/10382의 방향 필드 의미, `permissive`가 녹색 점멸인지). 방향·점멸을 현장 없이 풀 수 있는 사실상 유일한 경로다. 문안은 에이전트가 쓴다.
3. 그 답이 오기 전에는 숫자를 닫아 두는 쪽(B)을 권한다. 답이 명확히 오면 "현장 미검증" 영구 표기와 제보 1건 재폐쇄를 조건으로 한 개방(A)을 검토한다.

## 9. 사용자에게 필요한 결정 (5)

1. **숫자 개방 정책:** A. 공식 명세·자료 근거가 갖춰진 횡단만 열되 "현장 미검증"을 영구 표기하고 제보 1건이면 재폐쇄 / B. 현장 근거가 생길 때까지 닫음. 사용자는 "숫자가 닫힌 채로 공개하지 않는다"고 했으므로 B를 택하면 **앱 공개는 무기한 보류**가 된다. 팀 권고는 명세 답 전 B, 답 후 A 검토.
2. **T-Data 문의 글 1건을 로그인해서 올려 줄 수 있는가(5~10분).**
3. **Threads에 분석 결과·산수 같은 조각만 올리는 것을 "완성된 것"으로 볼 것인가, 프로필의 앱 링크는 걸 것인가.**
4. **"MVP 완성"의 뜻:** 숫자 닫힘(MVP-0)을 완성으로 부를지, 숫자가 열려야 완성인지. 내부 문서는 "MVP-0 완성(숫자 닫힘)"으로 적는다.
5. **켜는 순간을 "출발 전 계획"으로 가설 확정해 약속 문장에 넣을 것인가**(추천: 가설로 두고 반응으로 판단), 그리고 컨셉 한 줄 "서두르지 않아도 되는 길"은 훅이 아니라 우산 컨셉으로 쓰고 별도 훅 문장을 찾을지.

## 10. 확인하지 못한 것

그늘로 앱 내부(횡단 신호 정보·걸음 개인화·온보딩), 10만 명 정의, 유지율, 광고 수익, 개발자 SNS 운영 방식, 수요(인터뷰 0건), 서울 신규 통합 신호 API(10381/10382)의 권한·쿼터, 속도 기준·사망 통계의 원자료, 실제 휴대전화 보행 0회.
