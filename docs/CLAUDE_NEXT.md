## 1. 데모 전에 남은 것 (데모 회의 2번 표 중 남은 것)
1. **뒤로가기·새로고침:**
   - 화면마다 `history.pushState`, 뒤로가기는 앞 화면으로 간다. 안내 중이면 앱 안 확인 시트(`refConfirm`)로 "끝낼까요?"를 묻는다.
   - 걷는 상태(경로·진행·시작 시각)를 sessionStorage에 두고, 새로고침하면 이어 간다.
2. **미리 걸어보기(시뮬레이션):**
   - 경로 화면 버튼 하나로 가짜 위치를 경로 따라 움직여 안내·신호 띠·요약을 보여 준다.
   - 화면과 이미지에 "시뮬레이션"을 표시하고, 걸음 기록·속도 학습에는 넣지 않는다.
3. **신호 아이콘 겹침:** 축소했을 때 가까운 아이콘을 묶어 "+N"으로 보이거나 숫자를 숨긴다(시청 주변).
4. **"평일 오후 2시 기준으로 보기":** 신호 기록이 적은 시간대(`refThin()`)에 예시 시각으로 지도를 보는 버튼. 화면에 늘 "(예시 시각·예상)"을 붙이고, 길찾기 계산 시각과 섞지 않는다.
5. **사용 기록 확인:** 운영에서 검색·경로 선택·걷기 시작을 한 번씩 하고, `route_search`·`selected_route`·`walking_started`가 Redis(`events:YYYY-MM-DD`)에 쌓였는지 확인한다. 값은 출력하지 않고 개수만 확인한다.
6. **큰 자료 캐시:** 버전 이름과 오래 캐시를 쓴다(`tiles/*`, `signal-hours/*`, `search.json`, `vercel.json` headers). 첫 이용 약 20.6MB, 타일 b41 2.17MB.
7. **안내 중 신호 말풍선이 화면 오른쪽에서 잘림**(QA 캡처 p5-nav).

## 2. 지하철·버스 (`docs/TRANSIT_PLAN.md`)
1. **지하철 "이번/다음 열차" 판단 켜기:**
   - 평일 낮에 실제 `/api/subway-arrival` 응답 형식을 확인한다(`barvlDt`, `arvlMsg2`, `updnLine`, 역 이름 정리).
   - 맞으면 `REF_TRAIN_FIT=true`로 켠다.
   - 탈 만한 열차 하나만 강조하고, 못 타는 열차는 흐리게, 문구는 "이번 열차는 어려워요(예상)".
2. **걷는 중 역 도착 안내:** 역이 도착지면, 걷는 중 남은 거리로 다시 계산해 "이 열차 기준으로 천천히 가도 돼요"를 보여 준다. 뛰라는 말은 하지 않는다.
3. **버스(사용자가 "서울특별시_정류소정보조회" 활용신청을 추가한 뒤):**
   - `/api/bus-arrival?lat&lon`(주변 정류소)과 `?ars=`(정류소 도착)가 실제로 응답하는지 확인한다.
   - 확인되면 홈 지도에 정류소 아이콘, 장소 카드에 노선별 도착(첫째·둘째)을 붙이고, 정류소가 도착지면 지하철과 같은 판단을 넣는다.
   - 승인 전에는 화면에 버스 입구를 만들지 않는다. `/api/transit-status`의 `bus:true`는 키가 있다는 뜻일 뿐이다.
4. **대중교통 길찾기(ODsay 키가 생기면):** [대중교통 | 도보] 탭, 경로 카드(총 시간·요금·환승·노선 색 막대·첫 차 실시간 도착), 경로 상세. 걷는 구간은 쭉고 엔진(덜 부담스러운 길 + 신호 대기)으로 다시 계산한다.
