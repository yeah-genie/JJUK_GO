# 현재 제품 방향: 비슷하게 걸리면, 덜 힘든 길

갱신: 2026-10-28 (Asia/Seoul). 이전 ChatGPT 대화와 사용자 Threads 게시물을 다시 읽고 복원한 제품 방향이다.

## 사용자 확인 사항

서비스 전체를 설명하는 포지셔닝 후보는 [POSITIONING.md](../PRODUCT_DEFINITION.md)의 ‘내 페이스를 지키는 길찾기’다. 이는 이번에 추가한 에이전트 제안이며 사용자 최종 확정은 아니다. 아래의 신호+경사+계단 Walking 확장 방향과 구분한다.

쭉고는 신호 대기를 줄이는 기능에서 출발했지만, 목표를 **작은 시간 차이 안에서 덜 끊기고 덜 힘든 도보 경로를 고르는 서비스**로 확장한다.

- 이번 Walking 확장: **신호·오르막/경사·계단**을 함께 비교한다.
- 지하철·버스는 지금 구현하지 않는다. Walking 가설과 반복 사용을 먼저 검증하고 이후 검토한다.
- 사용자에게 추가시간과 줄어드는 불편을 직접 보여준다. 한 개의 불투명한 종합 점수부터 만들지 않는다.
- ‘모든 사람이 1~3분 더 걸어도 편한 길을 택한다’는 사실은 확인되지 않았다. 허용 우회시간과 요소별 가중치는 검증할 대상이다.

3. [Threads 참고 연구 게시물](https://www.threads.com/@1sanganatomy/post/DfB1hKxFAw8): 아래 세 논문을 게시물 본문에서 확인했다.
4. [Threads 최초 소개 게시물](https://www.threads.com/@1sanganatomy/post/DfAeUIWE7EL): 신호에 덜 멈추는 경로라는 출발점과 시안 수치가 예시라는 설명을 확인했다. 댓글을 근거로 요구사항을 만들지는 않았다.

이전 답변에 있던 연구 수치·데이터 갱신일·이용조건은 이전 대화의 주장이다. 새 분석이나 외부 발표에서 사용할 때 해당 원문·공식 데이터 페이지를 다시 확인한다. 강남역 조사 결과를 한국 보행자 전체의 비율로 일반화하거나, 보행취약계층 결과를 일반 보행자 계수로 적용하지 않는다.

## 제품의 핵심 비교

아래 숫자는 기능 설명을 위한 예시이며 실제 계산 결과가 아니다.

| | 빠른 길 | 덜 힘든 길 |
|---|---|---|
| 예상 시간 | 12분 | 13분 20초 |
| 신호 | 5곳 | 2곳 |
| 계단 | 있음 | 확인된 계단 없음 |
| 오르막 | 많음 | 적음 |

사용자가 판단할 문장: **‘1분 20초 더 걸리지만 신호 3곳과 계단 구간을 줄일 수 있어요.’**

실제 화면에서는 ‘많음/적음’을 가능한 경우 누적 상승고도·오르막 거리 등 계산된 수치로 바꾼다. 계단 미검출을 계단 없음으로, 표고 누락을 평지로 표현하지 않는다. 데이터가 없으면 ‘미확인’으로 둔다.

출발 시각 추천은 이 서비스의 한 기능이다. 경로를 선택하는 비교와 선택한 경로의 출발 시각 조절은 둘 다 유지하되 한 화면에서 계산 기준을 섞지 않는다.

## 현재 구현과의 차이

| 항목 | 코드에서 확인한 현재 상태 | 확장에 필요한 일 |
|---|---|---|
| 신호 | 알려진 신호의 패턴 대기와 멈춤 계산, 미관측 신호 별도 표시 | 예측 범위·누락 대기 표시를 통계와 연결 |
| 계단 | `scripts/build_seoul_map.py`가 지상 `highway=steps`를 등급 3으로 분류. 지도에도 계단 스타일 있음 | 경로별 계단 구간 길이·연속 구간 수 집계, 출처/누락 확인. 육교는 분류 순서상 등급 4가 될 수 있어 계단과 입체보행 속성을 분리할 필요 검토 |
| 경사 | 현재 그래프 생성·프로토타입에서 표고/누적 상승량 계산 구현을 확인하지 못함 | 적합한 표고 자료와 해상도·출처 확인, 방향별 상승량·경사 구간 산출 |
| 시간 허용 | 현재 `SLOW_OK=30`으로 쭉고 대안의 추가시간을 제한 | 기존 값을 곧바로 3분으로 바꾸지 말고 +60/+120/+180초 예산별 대안 실험 |
| 선호 | `STOP_COST=15` 등 현재 휴리스틱 사용 | 기존 휴리스틱과 신호·계단·경사에 대한 사용자 선호 계수를 구분 |
| 대중교통 | 이번 범위에 없음 | Walking 검증 이후 별도 설계 |

신호가 같은 시간에 많이 있어도 각 계단·오르막 수치가 사용자 불편의 크기를 그대로 의미하는 것은 아니다. 계단 한 구간을 피하는 값과 우회시간의 교환비는 임의로 확정하지 않는다.

## 이전 대화의 단계별 제안 — 실행 계획으로 복원

순서의 취지는 유지하되 수량·임계값은 실험 설계 제안이며 아직 사용자 검증 결과가 아니다.

| 단계 | 할 일 | 다음 단계 판단 |
|---|---|---|
| 0. 방향 문서화 | 신호+경사+계단의 Walking 서비스로 정의 | 이번 문서와 사용자 정정으로 복원 |
| 1. 데이터 점검·통합 | OSM 계단 추출 확인, 서울시 계단도로 자료 후보 재확인, 표고 자료 조사 | 출처·사용조건·정확도·누락 범위를 설명할 수 있는가 |
| 2. 대안 경로 실험 | 평지/신호형, 경사/계단형, 혼합형 지역에서 빠른 길과 +1/+2/+3분 예산의 대안 비교 | 작은 우회로 불편을 줄이는 대안이 실제로 존재하는가 |
| 3. 선택 실험 | 추가시간·신호·계단·경사 조합을 바꾼 비교 문제로 선호 조사 | 사람들이 어떤 조건에서 우회를 고르는가 |
| 4. 실제 사용 검증 | 예측/실제 시간·대기·계단·경사·체감 피로 비교 | 계산과 현장, 표시와 사용자 이해가 맞는가 |
| 5. Walking MVP | 빠른 길과 덜 힘든 길을 제공하고 선택 이유·재사용 확인 | 반복 사용 가치가 있는가 |
| 6. 개인화 | 선택·보행 속도 데이터가 충분할 때 보정 | 충분한 개인별 근거가 있는가 |
| 7. 후속 확장 | 필요가 검증되면 보행 혼잡, 그 후 지하철·버스의 환승·대기·혼잡 검토 | Walking의 가치·데이터가 증명됐는가 |

이전 채팅에서 제안한 규모는 OD 500~1,000쌍, 선택실험 100명×8~12문항, 실제 walking trip 30~50회였다. **완료된 실험도, 확정된 표본 설계도 아니다.** 실제 자원과 분석 방법에 맞춰 결정한다.

## 데이터 후보와 검증 항목

- 서울시 통행불편지역 공간정보의 계단도로: 이전 채팅에서 발견한 후보. 현재 제공 여부·구분코드·사용조건을 공식 페이지에서 재확인해야 한다. 서울 모든 계단을 완전하게 포함한다고 가정하지 않는다.
- OSM `highway=steps`: 기존 자료를 활용할 수 있다. `step_count`가 없는 것을 0칸으로 두지 않는다.
- 표고/경사: 자료 선정 전이다. 표고 해상도가 계단·육교·짧은 언덕에 적합한지, 육교 높이를 지표면 표고만으로 추정하지 않는지 확인한다.
- 원시 지표: 보행시간, 신호 대기/개수, 계단 유무·길이, 누적 상승고도, 경사 구간 거리, 데이터 출처·품질. 방향을 뒤집으면 상승고도도 재계산한다.
- 5%·10% 경사 구분은 이전 대화의 실험 후보이지 안전·접근성 인증 기준이 아니다.

## 이번 작업에서 바뀐 것

방향·로드맵·인수인계 문서를 정정했다. 경사/계단 라우팅이나 비교 UI를 구현한 것은 아니다. 기존 신호 기능 검토의 신뢰성·시연 표시 문제는 여전히 유효하지만, 그것만 해결하는 것을 전체 제품 목표로 삼지 않는다.
