## 3. 설문 — 콜드스타트의 추천 조건

### 1/2: 다른 사람과 걸으면?

문구는 승인 이미지와 같이 `다른 사람과 걸으면?`, 보조 `처음 길을 추천할 때 참고해요`. 답 네 개는 `조금 뒤처지는 편이에요`, `비슷하게 걷는 편이에요`, `앞서가는 편이에요`, `잘 모르겠어요`다. 상대 비교이므로 실제 속도 측정값으로 취급하지 않는다. 응답만으로 0.8/1.2/1.4m/s 같은 속도를 확정하지 않는다.

선택 전 다음은 비활성으로 두되 건너뛰기는 활성이다. ‘잘 모르겠어요’는 유효 응답이므로 다음으로 갈 수 있다. 보조 문구는 `걸음 속도는 걷는 동안 맞춰요`. 동의 없는 GPS 요청은 이 화면에서 시작하지 않는다.

### 2/2: 오늘 함께하는 것이 있나요?

`없음`, `유모차`, `보행 보조기`, `지팡이`, `무거운 짐`, `기타`를 선택한다. 진단명·나이·신체등급을 수집하거나 자유 입력을 요구하지 않는다. 실제 장애 여부를 추론하지 않는다.

- none을 선택하면 나머지를 해제한다. 다른 장비를 선택하면 none을 해제한다. 나머지끼리는 복수 선택 가능하다.
- 아직 선택하지 않음과 명시적 없음은 다르다. 건너뛰기는 미응답으로 남긴다.
- 유모차/보행 보조기 등은 ‘계단 피하기’의 **초기 추천**에만 반영할 수 있다. 무장애 경로 보장·고정 속도·장비별 의학 판단으로 바꾸지 않는다. 추천이 설정에 적용되면 사용자가 언제든 바꿀 수 있고 직접 바꾼 설정을 다음 추천이 조용히 덮지 않는다.
- 이 단계도 건너뛰면 홈으로 가며, 후에 설정의 `처음 답변 수정`에서 다시 고칠 수 있다. 오늘의 상황이라는 의미를 유지하고 영구 신체 프로필처럼 설명하지 않는다.

설문은 설정에서 수정할 때 draft를 갖는다. 취소/뒤로가기는 기존 답을 보존한다. 완료/적용 때만 저장·경로 재계산에 반영한다. 설문 전체를 건너뛰어도 앱의 검색·수동 출발·길찾기는 사용할 수 있다.

## 4. 홈과 개인 횡단 지도층

홈은 작은 브랜드·검색·출발 `내 위치`/변경·실제 지도·내 걸음 상태·최근 장소 최대 2개·주 행동으로 구성한다. 대형 서비스 설명·상단 마감 시각·수동 속도 숫자·운동 기록을 넣지 않는다. `내 위치로 출발`은 위치를 얻고 목적지가 없으면 목적지를 고르는 흐름으로 이어진다. 목적지 없이 바로 가짜 경로/걷기를 시작하지 않는다.

위치는 사용자 행동에 따라 요청한다. 거부/시간 초과/지원하지 않는 환경이면 `위치를 연결하지 못했어요`와 `지도에서 출발 선택`을 제공한다. 검색·조건 편집을 막지 않는다. 내 위치 점은 실제 유효 fix를 받았을 때만 표시한다. 시연 위치는 `예시 위치`로 구분한다.

지도층의 기본 범례는 **이력 있음 / 미확인**이다. ‘이력 있음’은 해당 자료가 있다는 뜻이며 방향·길이·개인속도까지 검증됐다는 뜻이 아니다. 미확인은 회색 점선+?로 표시하고, 통행 가능·안전·무장애·현재 초록으로 읽힐 녹색 체크를 쓰지 않는다. 지원 조건을 통과한 이후에만 개인 횡단 부담을 별도 상태로 제공한다. 사용자 속도 학습 전에는 개인화된 여유 초나 ‘쉬운 횡단’ 등급을 지도에 만들지 않는다.

## 5. 걸음 상태와 속도 우선순위

| 상태 | 조건 | 홈/설정 문구 | 개인 여유 초 |
|---|---|---|---|
| `unmeasured` | 인정 가능한 표본 없음 | `아직 측정 전` | 숨김 |
| `learning` | 유효 표본은 있으나 품질/양 부족 | `내 걸음을 알아가는 중` | 숨김 |
| `estimated` | 구현의 품질 기준을 통과한 보행 요약 | `내 걸음 반영` | 신호/길이 조건도 만족할 때만 |
| `manual` | 사용자가 직접 값을 명시적으로 적용 | `직접 정한 걸음` | 물리 자료 조건도 만족할 때 추정값으로만 |
| `paused` | 자동 맞춤 꺼짐, 직접값 없음 | `자동 맞춤 꺼짐` | 기존 값 유효성/정책에 따라 숨김; 기본값을 학습값으로 표시하지 않음 |
| `storage-unavailable` | 저장 거부/용량/파싱 오류 | `이번 이용 동안만 반영해요` | 세션 내 조건은 따르되 지속 저장으로 설명하지 않음 |

속도 선택 우선순위는 **사용자가 적용한 manual → 사용 가능한 learned estimate → 잠정 기본값**이다. manual 해제 시 유효 learned가 있으면 돌아가고, 없으면 잠정값을 쓴다. 설문 답은 이 세 값의 증거 수준을 올리지 않는다.

현재 작업의 개발 출발점으로 `DEFAULT=1.0m/s`를 잠정 사용하기로 한 것은 **구현상 가정이며 사용자 확정/현장 검증값이 아니다.** 초기 ETA 등에 쓰면 `임시 기준`으로 알린다. 큰 개인 여유 초의 gate를 통과시키는 데 쓰지 않는다. 구체 상수/범위는 모듈 한곳에서 관리하고 UI·검색·ETA가 서로 다른 값을 사용하지 않게 한다.

### 자동학습

자동으로 맞추기 선호는 기본 ON일 수 있지만 OS 위치 권한과 다르다. 지도 탐색/설문만으로 연속 추적을 시작하지 않는다. **사용자가 걷기 안내를 시작하고 위치 권한을 허용했을 때만** 시작하며 종료·취소 시 watch를 해제한다. 백그라운드 지속 측정을 약속하지 않는다.

유효 표본은 시간 증가·정확도·이동량·시간 간격을 확인해야 한다. GPS 튐, 긴 공백, 동일 시각 재전송, 너무 나쁜 정확도, 정지/신호 대기는 이동 페이스 학습에서 제외한다. 단말 `coords.speed` 하나만 믿지 말고 거리/시간과 대조한다. 신호 대기 포함 평균 여행속도는 움직일 때의 보행 속도와 분리한다. 한 번의 빠른 걸음·급한 이동·계단/경사 구간을 평소 속도로 즉시 덮지 않는다.

필터·유효 표본량·안정성·과거 가중치의 수치는 모듈 구성값과 시험으로 남긴다. 임계치를 넘었다고 실제 개인속도 정확도가 실증됐다는 뜻은 아니다. 시연 타이머로 ‘학습 완료’를 만들거나, 근거 없는 90% 정확도/건강 진단을 표시하지 않는다. 이동 조건이 달라진 날에는 적응·수정·초기화가 가능해야 한다.

**수동 속도 조정은 `settings-manual` 안에만 둔다.** km/h 표시와 내부 m/s 변환은 한 곳에서 수행한다. UI min/max/step는 실제 학습 모듈의 지원 범위와 일치시킨다. 낮은 속도를 지원하지 않는다면 조용히 더 빠른 값으로 올리지 말고 미지원 이유를 표시한다. 정해지지 않은 범위를 이미지의 2.0–5.0km/h에 맞춰 하드코딩하지 않는다. 바뀐 속도는 경로 캐시 키·검색 비용·시간 시뮬레이션·예상 도착·걷기 남은 시간에 함께 적용한다.

## 6. 결과와 신뢰 gate

기본 결과는 출도착 툴바, 두 후보 지도, 짧은 경로 행, 정보 없는 횡단 수, 계산 기준, 행동 바다. 계단/추가시간/속도는 설정으로 이동한다. 동일한 후보는 두 길처럼 반복하거나 개선 효과를 꾸미지 않는다.

### 수치 노출 gate

다음 조건을 **모두** 통과해야 정적 개인 횡단 여유 초를 보여준다.

1. 개인속도가 `estimated` 또는 유효 `manual`이며 해당 근거/범위가 있다.
2. 물리적 횡단보도와 올바른 방향의 신호 필드 매칭이 검증돼 있다.
3. 고정녹색/점멸/적색 의미와 진입 가능 구간이 분리돼 있다. `permissive`라는 문자열만으로 점멸을 확정하지 않는다.
4. 횡단거리와 단위·대상 구간이 확인돼 있다. 차선 수 환산값만 있으면 개인 여유 큰 숫자를 확정해서 노출하지 않는다.
5. 적용 날짜·시간대·요일/휴일 조건에 충분한 근거가 있으며 지원 밖·패턴 불일치·오래된 자료를 판정한다.

현재 정적 자료에 이런 검증 증거가 없다면 gate는 fail-closed, 기본은 **`정보 없음`/`자료 확인 중`**이다. evidence flag를 없다고 기본 true로 두지 않는다. 개발 fixture는 별도 `?demo=1` 등 시연 모드와 `시안/시연용 예시` 표시에서만 허용하고 일반 모드에 새지 않게 한다. 승인 이미지의 `~12초`를 상수로 출력하지 않는다.

여유는 `보행 녹색 시작을 기준으로 한 시간 예산 − 횡단거리/개인속도`라는 **정적 가정의 차이**다. 완료 시간을 위한 구간과 새 진입 가능한 구간을 구분해야 한다. 실제 도착 순간의 잔여시간, 새 진입 허가, 현재 초록 예측, 안전 보장이 아니다. 수치 옆 `초록 시작 기준`과 계산 기준 상세를 유지한다. 여유가 음수면 부호를 제거하거나 0으로 바꾸지 않는다.

경로 대표값은 확인 가능한 횡단 중 가장 빠듯한 여유이며, 모르는 횡단이 있으면 그 수를 반드시 붙인다. 모름이 있는 길의 부분 최솟값을 전체 경로의 여유라고 단정하지 않는다. 검증된 여유가 없는 후보는 `여유 있는 길`보다 `편한 길 후보`처럼 근거 수준에 맞는 이름을 쓴다. 추가시간 예산을 넘는 후보를 추천처럼 제시하지 않는다.

지금 앱의 신호 최소대기/길 계산을 바꿔 정확성을 보장하는 작업까지 이번 시각 변경에 묶지 않는다. 종전 `MIN_GREEN=8`, 방향 가정, 미확인 45초, 제한 후보 탐색은 계산 기준과 미완료 항목으로 남기고, UI의 새 큰 숫자를 정당화하는 근거로 쓰지 않는다.

### 계산 기준 상세

기본 화면의 긴 면책을 대체하되 정보 자체를 삭제하지 않는다. 상세에서 속도 근거(직접/학습/임시), 신호 기준 날짜/시간대·실시간 아님, 방향/길이 검증 수준, 미확인 횡단, 계단·지형 추정 출처와 지원 범위를 읽을 수 있게 한다. 원시 키·토큰·내부 스택은 노출하지 않는다.

## 7. 걷기 설정의 적용·취소

`자동으로 맞추기`, 학습 상태, 접힌 `직접 정하기`, `처음 답변 수정`, `이 기기에 요약 저장`, `학습 초기화`를 기본 순서로 둔다. 길 조건 `계단 피하기`와 `더 걸어도 되는 시간`도 설정 안에서 수정 가능하다. 기본 화면에 여러 슬라이더/선호를 펼쳐 두지 않는다.

설정 진입 시 현재값을 draft로 복사한다. `적용`은 유효 값만 반영하고 변경된 조건으로 경로를 다시 계산한 뒤 진입한 화면으로 돌아간다. 뒤로가기/취소는 draft를 버리고 원래 경로와 값을 유지한다. 설문 수정도 같은 원칙이다. 설정에서 바꾸지 않은 조건은 보존한다. 계산 도중 더 최신 요청이 생기면 오래된 응답이 선택 경로를 덮지 않게 한다.

요약 저장 ON/OFF는 자동측정 ON/OFF와 별개다. 저장 OFF여도 동의한 현재 안내 중에는 RAM에서 학습할 수 있지만 세션 이후 지속한다고 약속하지 않는다. OFF/초기화 때 기존 저장 요약의 제거 범위를 명료하게 하고 부모 구현의 최종 정책과 시험을 맞춘다. 학습 초기화는 속도 요약만 지우며 별도 선호·최근 장소·설문까지 함께 지우지 않는다. destructive 버튼은 범위를 설명하고 취소 가능한 확인을 제공한다.

## 8. 보관 데이터와 마이그레이션

계정·서버 전송은 이번 필수가 아니다. 요약은 로컬에 선택적으로 저장한다. 브라우저 localStorage를 쓰더라도 무조건 이용 가능하다고 가정하지 않는다. 저장 오류는 현재 이용을 막지 않는다.

저장 스키마는 version을 포함하고 아래 논리 필드를 가진다. 실제 key 이름을 바꾸면 마이그레이션과 검증 보고서에 최종 이름을 기록한다. 키를 여러 함수에 문자열로 반복하지 않는다.

| 논리 묶음 | 저장 가능 | 저장하지 않는 것 |
|---|---|---|
| onboarding | schema version, 완료/건너뜀, 상대 걸음 답, 장비 enum, 수정시각 | 나이·진단·미응답을 추측한 장애 상태 |
| preferences | auto 선호, summary 저장 선호, 사용자가 직접 정한 속도/단위, 계단 선호, 추가시간 | 설문 답을 실제 측정값으로 바꾼 속도 |
| pace summary | 인정 이동시간·거리/표본수·집계 속도/분산·유효성·갱신 시각 등 최소 요약 | 연속 위경도, 타임스탬프별 이동 궤적, 원시 GPS 로그 |
| session | 현재 경로, 선택 후보, 임시 GPS fix, 설정 draft | 종료 후 강제 영구 저장·숨은 전송 |
| recent places | 사용자가 선택한 장소 최소 정보, 삭제 가능 | 실시간 위치 이력·백그라운드 위치 로그 |

기존 `jjukgo:pace`나 다른 legacy profile을 발견해도 데이터 형식과 유효 범위를 검증한다. 예전 preset/기본값을 `estimated`로 승격하지 않는다. 원자료나 fitness 기록 screen을 되살리는 이유가 되지 않는다. 깨진 JSON·알 수 없는 version·NaN/Infinity·음수 이동량은 안전하게 무시/복구하고 앱이 열려야 한다.

## 9. 실패 상태와 기본 문구

| 상태 | 사용자에게 보일 내용 | 가능한 다음 행동 |
|---|---|---|
| 위치 권한 전 | `내 위치는 허용할 때 연결해요` | 사용자 버튼으로 권한 요청/지도 선택 |
| 권한 거부/실패 | `위치를 연결하지 못했어요` | 다시 시도/지도에서 출발 |
| 위치 품질 나쁨 | `위치가 정확하지 않아 확인 중이에요` | 측정 보류, 수동 출발 선택 가능 |
| 지도/데이터 실패 | `지도를 불러오지 못했어요` | 재시도; 빈 지도 위 가짜 경로 금지 |
| 경로 없음 | `연결되는 보행 경로를 찾지 못했어요` | 실제 출입구/다른 지점 선택 |
| 신호 모름 | `정보 없는 횡단 N곳` | 상세·지도층; 0회 대기/0초로 대체 금지 |
| 학습 전 | `아직 측정 전` | 평범한 검색·길찾기 계속 가능 |
| 학습 부족 | `내 걸음을 알아가는 중` | 현재 안내 이어가기, 직접 설정 선택 가능 |
| 측정 종료/백그라운드 공백 | `위치가 끊겨 측정을 잠시 멈췄어요` | 복귀 후 재연결, 공백을 걸은 거리로 추정하지 않음 |
| 저장 불가 | `이번 이용 동안만 반영해요` | 저장 없이 계속, 반복 경고 금지 |

걷는 중 화면은 회전·경로 진행에 집중한다. 현재 위치가 멀어지면 이탈을 명료하게 알리고 재탐색을 선택할 수 있다. 위치 점이 경로 끝에 근접했다는 이유만으로 실제 건물 출입구 도착을 보장하지 않는다. 안내 종료 시 GPS watch·임시 타이머·오래된 비동기 요청을 정리한다.

## 10. 검증·완료 기준

### 화면/상태 시험

1. 첫 방문·건너뜀·다시 수정·새로고침 후 홈 복귀를 시험한다. 설문 미응답과 명시적 없음은 보존된다.
2. 장비 none의 배타성, 복수 장비, 직접 바꾼 계단 선호 보존, 설문 수정 취소/적용이 맞는다.
3. 홈/결과에 수동 속도 슬라이더가 없고 설정 하위에서만 조절된다. 학습 전 수동 숫자가 ‘내 측정값’처럼 보이지 않는다.
4. 실제/가짜 GPS를 분리한 시험에서 정지·튀는 점·긴 공백·권한 거부·종료 후 callback·설정 OFF가 요약을 오염시키지 않는다. 실제 야외 시험과 가짜 GPS 시험을 구분한다.
5. manual/learned/provisional 변경마다 검색·ETA·남은 시간·캐시가 같은 기준으로 갱신된다. 시각 승인으로 개인속도 정확도 시험을 대신하지 않는다.
6. 개인속도 또는 신호 물리 근거 중 하나라도 빠지면 여유 초가 숨겨진다. fixture의 12초/18분이 일반 모드에 나오지 않는다. 여유가 음수/혼합 모름인 경우도 시험한다.
7. 선택 경로가 지도 강조·리스트 상태·걷기 시작에 동일하게 적용되고 동일 경로 두 개를 과장하지 않는다.
8. localStorage 오류·깨진 legacy JSON·저장 OFF·학습 초기화·다시 방문에서 개인정보/상태 문구가 실제 동작과 맞는다.
9. 360×640, 390×844, 768×1024, 가로 및 200% 글 확대에서 모든 조작/CTA가 접근 가능하다. 스크롤바 미노출과 실제 스크롤을 각각 검사한다. 세부 색/터치/대비는 DESIGN_SYSTEM의 기준을 따른다.
10. 빌드 산출물 `docs/prototype/index.html`이 소스와 동기화되고, 실제 공개 배포가 어느 commit인지 확인한다. 로컬 통과·push·Vercel READY·공개 브라우저·실제 휴대전화 보행을 별도 증거로 적는다.

### Claude에게 남길 미완료

현재 UI 구현이 끝나도 다음은 완료로 승격하지 않는다: 방향 코드 현장 매칭, 국내 permissive/점멸 정의, 정확한 횡단거리·단위, 날짜/요일 일반화, 실시간 신호 예측, GPS 학습의 개인별 현장 정확도, 노면·턱·보도 폭·시설 상태를 포함한 무장애 연결, 백그라운드 지속 위치, 소음/그늘/PM의 실시간 회피. 실제 자료가 생기면 근거 metadata와 gate를 보강한 뒤 숫자를 노출한다.
