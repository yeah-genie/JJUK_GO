# 쭉고 · 첨부 이미지 기준 데모

상태: 별도 프로토타입. **기본 브랜치 병합·운영 배포는 하지 않았다.**

10/31 후속: 과거 신호 지속시간 요약과 보행 부담 비교를 연결했다. 원본 재생성은 기존 빌드 명령이 `build_reference_signal_facts.py`도 실행한다. 다른 시간의 과거 기록은 출처와 ‘현재 신호 아님’을 표시하며 현재 위상 예측에는 쓰지 않는다. 측정 전은 자동 맞춤, 경로는 예상 보행/신호 대기 별도다. 계획 화면은 계단·급경사·상승과 펼치는 비교로 구성하며 유효 대안이 있을 때만 두 경로 선택을 보여준다. 급경사 덜 걷기는 기존 유효 후보 중 우선순위를 바꾸는 것으로 완전 회피를 보장하지 않는다. [데이터와 구현 상세](../../../reports/reference-ui/BARRIER_FREE_2026-10-31.md). 아래 초기 구현의 ‘급경사 준비 중’ 설명은 이 후속으로 대체됐다.

## 사용자 결정

첨부 `codex-clipboard-c4111d64-add1-4949-9d70-d482a58400f6.png`의 5개 화면만 시각 기준으로 삼는다. 새 디자인/다크 테마/대시보드/과한 카드/새 내비게이션을 제안하지 않는다. 지도 비율, 카드, 여백, 타이포, CTA 위치를 390×844에 맞춘다. 이후 사용자가 추가로 승인한 것은 기존 Vercel 시작 로고의 복원, 네이버 지도, 실제 데이터 연동, 신호 아이콘 클릭 상세 정보다.

핵심은 **최단 거리만이 아니라, 조금 더 걸려도 내 조건에서 부담을 줄이는 길**이다. 대안이 기존 경로 비교 기준을 통과하지 않으면 더 편한 길을 꾸며 내지 않는다.

## 실행과 두 모드

```text
python scripts/build_reference_ui.py
node scripts/preview.cjs
```

- 실제 데모: http://127.0.0.1:8771/reference-ui/demo.html
- 원본과 비교하는 5화면: http://127.0.0.1:8771/reference-ui/preview.html
- 실제 앱 직접 열기: /reference-ui/index.html
- 화면 직접 열기: /reference-ui/index.html?sample=1&screen=home (search/settings/walking/summary)

`sample=1`은 원본의 4.8km/h, 74m, 17초, 15분, 1.1km, 40초를 재현하는 **시각 검증용 예시**다. 실제 신호·GPS·이동 기록이 아니다. 제목과 검토 도구 바깥 안내에 명시하며 운영 설정과 섞지 않는다. 손으로 지정한 예시 지도 경로는 길찾기 정확도의 증거가 아니다. 앱 화면을 통째로 이미지로 붙인 구현도 아니다.

실제 모드는 기존 서울 장소·보행 그래프·계단/경사·신호 패턴·GPS·걸음 학습을 이용한다. 길찾기 후 같은 지도 화면에서 편한 이유를 보고 **걷기 시작**을 눌러야 GPS 기록을 시작한다. 위치를 모르면 직접 출발지를 고를 수 있다. 처음 홈은 ‘아직 측정 전’이며 수동 속도를 강요하지 않는다.

## 네이버 지도

새 Maps 상품 Dynamic Map(Web JS)을 연결했다. `NAVER_MAP_CLIENT_ID`를 프로젝트의 `.env.local`에 설정하면 로컬 미리보기가 읽는다. 이 파일은 Git에서 제외된다. Vercel에 나중에 적용할 때도 해당 환경 변수만 넣는다. Client Secret은 필요 없으며 코드·채팅·GitHub에 넣지 않는다. `/api/map-config`는 브라우저 공개용 Client ID 하나만 반환한다.

사용자 콘솔의 등록 URL은 localhost, 127.0.0.1, `jjukgo.vercel.app` 도메인을 직접 확인했다. 등록 내용을 임의로 바꾸지 않았다. API는 공식 `ncpKeyId` 로딩 방식이다. SDK 클래스 준비, 부모 기준 지도 크기, 최초 `tilesloaded`, 화면 전환 시 취소와 정리를 처리한다. 지도 자체의 로고/출처는 가리지 않는다. 실제 키로 네이버 지도 타일·파란 실제 경로 표시를 로컬 브라우저에서 확인했다. 상세: [NAVER_SETUP](NAVER_SETUP.md).

네이버는 지도 표현을 맡는다. 보행 경로 계산을 자동차용 Directions 5로 바꾸지 않는다. 장소 검색은 기존 서울 로컬 자료와 명시적 클릭의 공개 Photon 검색을 유지한다.

## 신호 데이터와 표시

- 2026-10-31 저녁 재확인: 원격 기본 브랜치 `67e7788`의 최신 신호 이력/시간대 조각만 가져왔다. **10/14–10/30, 17일, 패턴 후보 교차로 1,734곳**이다. 후보 수는 검증된 횡단 수가 아니다.
- `data` 브랜치에서는 09:42–10:02 UTC(18:42–19:02 KST)에 약 5분 간격의 성공 호출을 확인했다. 새벽에 관측했던 timeout/404가 계속된다고 단정하지 않는다. 호출 간격과 모든 교차로의 성공 갱신 주기는 다르다.
- 실제 실시간 지도 설정은 여전히 꺼져 있다. 오래된 API 잔여시간을 현재 카운트다운으로 이어 쓰지 않는다.
- 새 화면이 회색으로 고정하던 부분을 제거했다. 신호 ID·방향·길이가 있는 `route.x`와 기존 `signalPlan/planConfidence/SIG.predictX`를 연결한다. 개수용 `route.m.xlist`만 보고 신호를 추측하지 않는다.
- 신뢰 기준을 통과하면 초록/대기 **패턴 예상**과 남은 시간을 보여 준다. 1초마다 내용만 갱신하며 지도 위치를 다시 맞추지 않는다. 점선 테두리와 ‘실시간 아님’으로 실제 관측과 구분한다. 기존 검증 임계값을 완화하지 않았다.
- 아이콘을 누르면 그 위치에 붙은 상세 창 한 개가 열린다. 상태/잔여시간, 자료 기간, 미확인 이유를 볼 수 있다. 닫으면 기존 다음 횡단 말풍선이 돌아온다.
- 현재 추정을 검증할 수 없지만 충분한 표본의 이력 구간은 있으면, ‘신호 기록 있음’과 ‘기록상 초록 구간(이력 추정)’을 표시한다. 이를 현재 남은 초로 표현하지 않는다.
- 시간 계획이 없어도 위치 자료가 있는 주변 신호는 회색으로 표시한다. 네이버 지도 이동 완료 시 현재 중심 근처 자료를 최대 24방향까지 갱신하며 경로 연결 횡단은 별도로 보존한다. 종로 한정 자료가 아니지만 성신여대 등 지역·요일·시간별 이력 범위는 제한된다. [성신여대 범위와 사용자 점검](../../../reports/reference-ui/audit-2026-10-31/REVIEW.md).
- 예를 들어 기존 기준으로 주말 18시 조각에서는 46방향이 통과했으나, 확인 당시 19시 조각에서는 날짜 간 비교 기준을 통과한 방향이 없었다. 시간대·요일에 따라 숫자가 닫히는 것은 자료의 한계이며 가짜 숫자로 채우지 않는다. 이후 데이터가 바뀌면 다시 검증한다.

새벽 기준 조사와 원인 분석은 [DATA_INTEGRATION](DATA_INTEGRATION.md)에, 최신 확인은 그 문서의 추가 기록에 남긴다.

## 구현 경계

- 보이는 UI: `shell.html`, `ui.css`, `ui.js`. 기존 카드 HTML/CSS를 보이는 화면에 재사용하지 않았다.
- 기존 엔진이 DOM에 결합되어 있어 `hidden inert aria-hidden` 호환 DOM을 둔다. 운영 통합 시 분리할 기술 부채이며 실제 화면은 아니다.
- `build_reference_ui.py`는 전용 `reference-ui/index.html`만 생성한다. 운영 `docs/prototype/index.html`, `src/` 알고리즘, 수집 워크플로, 신호 신뢰 기준은 수정하지 않는다.
- 저장 키 `jjukgo:reference:`는 운영과 별도다. 익명 로그 송신은 이 프로토타입에서 끈다. 좌표 궤적은 메모리에만 두며 이미지 저장을 명시적으로 눌렀을 때 내보낸다.
- 자동 학습 OFF는 마지막 학습 속도를 유지한다. 수동 속도를 고를 때만 수동 모드가 된다. 실제 검색은 원본 캡처의 4행 제한과 달리 기존 최대 40개 결과를 유지한다.
- 급경사 지표 비교는 기존 엔진을 쓴다. 독립적인 급경사 완전 회피는 준비 중으로 표시하고 실제 토글은 비활성화했다. 계단 회피는 기존 조건을 쓴다.
- 첫 로고는 기존 쭉고 SVG/브랜드 폰트를 재사용한다. 첫 방문 3.2초, 건너뛰기, 움직임 줄이기를 지원한다. 다섯 기본 화면은 밝은 디자인을 유지한다.
- 걷기 지도 558px(66.1%), 하단 286px. 다음 마커 45px, 나머지 25–36px. 말풍선은 지도 좌표에 연결한다.
- PNG 저장은 밝은 요약과 기존 OSM 지도 캔버스를 내보내며 OSM 출처를 표시한다. 네이버 타일을 무단 캔버스 복사하는 방식이 아니다.

## 검증과 남은 사항

기존 Node 핵심 검사 4개, `check_reference_ui.cjs`, Python 83개 검사를 통과했다. 실제 장소 검색/경로 계산/계획 상태/네이버 지도/신호 상세는 브라우저로 확인한다. 시각 근거와 상태는 [design-qa](design-qa.md), 스크린샷은 `reports/reference-ui/screens/`다.

실제 야외 GPS 이동·자동 학습의 정확도와 실제 신호의 현장 대조는 미검증이다. 예시 종료를 실제 이동 기록으로 저장하지 않는다. 새로운 실시간 신호를 열거나 신뢰 조건을 낮추려면 별도 근거가 필요하다. 이 데모의 운영 반영은 사용자 검토 후 별도 작업이다.
