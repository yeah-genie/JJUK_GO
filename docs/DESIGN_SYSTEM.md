# 쭉고 디자인 시스템 — Asphalt

2026-10-29 · 승인된 시안을 실제 웹 UI로 옮기는 시각·컴포넌트 계약이다. 기능과 데이터 판정은 [PRODUCT_SPEC.md](PRODUCT_SPEC.md), 제품 방향은 [PRODUCT_DEFINITION.md](PRODUCT_DEFINITION.md)를 따른다. 이 문서의 존재는 구현·배포·실기기 검증 완료를 의미하지 않는다.

## 1. 승인 시안과 해석 범위

시각 기준은 `reports/ui/2026-10-29/asphalt/`의 `onboarding.png`, `home.png`, `result-learned-example.png`, `auto-pace-settings.png`다. 이미지의 지도·건물·경로·시간·여유 숫자는 생성형 시안이다. 실제 지리, 통행 가능성, GPS 위치, 신호 검증 자료로 복사하지 않는다. 실제 지도 엔진과 저장소 데이터를 스타일링해 사용한다.

유지할 것은 **짙은 무광 아스팔트, 차선 노랑, 횡단 표식, 적은 글, 지도와 짧은 경로 행**이다. 화면 전체를 카드에 넣거나 흰 UI를 단순 반전하지 않는다. 질감은 선택 사항이며 실제 지도와 글의 가독성보다 우선하지 않는다. 제품 안에 생성 시안 이미지를 화면 배경으로 넣어 조작부를 흉내 내지 않는다.

제거된 이전 요소: 중앙 대형 로고, 홍보 헤드라인, 노란 테두리의 큰 경로 카드, 큰 라디오 버튼, 결과 안의 여러 설정 칩, CTA 아래 장문 면책, 시간 막대, 독립 기록/운동 대시보드. 과거 `UX.md` 등의 화면 설명은 현재 디자인 계약이 아니다.

|---|---|---|
| `--bg` | `#242A32` | 앱 바탕·상단·하단 |
| `--surface` | `#303844` | 검색 입력·작은 제어면 |
| `--line` | `#46505D` | 장식적인 구분선, 지도·행 경계 |
| `--control-line` | `#8793A3` | 입력·토글·선택기의 식별 가능한 외곽선 |
| `--text` | `#F4F2E9` | 제목·본문·수치 |
| `--muted` | `#B7BEC8` | 설명·측정 상태 |
| `--yellow` | `#F6C343` | 주 행동·선택 경로·강조 수치 |
| `--on-yellow` | `#242A32` | 노란 버튼의 글·아이콘 |

| `--map-park` | `#3E5948` | 공원·녹지의 기준 톤 |
| `--map-label` | `#F4F2E9` | 지도 글자; 어두운 halo로 구분 |

지도 색은 위 값을 출발점으로 데이터 레이어별 조정한다. 길을 찾는 데 필요한 보행로·횡단·통로와 글을 어둡게 지우지 않는다. 노란 경로가 녹지나 도로 위에서 구분되도록 짙은 외곽선을 함께 쓴다. 위치 파랑은 플랫폼 관습에 따른 현재 위치에 한정한다. 적색·초록을 현재 진입 허가/금지로 쓰지 않는다.

평면 sRGB 토큰의 계산 대비는 `--text`/`--bg` 약 12.89:1, `--muted`/`--bg` 7.72:1, `--muted`/`--surface` 6.32:1, 노랑/아스팔트 8.82:1이다. 실제 렌더의 투명도·지도 배경까지 검사해야 한다. `--line`/`--bg`는 약 1.77:1이므로 조작부나 의미를 이 선 하나로 표현하면 안 된다. 본문 4.5:1, 큰 글 3:1, 중요한 제어 외곽/포커스 3:1 이상을 완료 기준으로 삼는다.

## 3. 글·간격·모양

- 글꼴은 프로젝트의 한국어 sans를 우선한다. Pretendard/Noto Sans KR 계열과 시스템 sans fallback을 두며 웹폰트 실패에도 줄바꿈·버튼 크기가 유지돼야 한다.
- 본문 16px/1.5, 짧은 보조 14px/1.45, 화면 제목 20–22px/1.3, 경로 시간·여유 26–32px/1.15. 설문 질문만 28px까지 허용한다. 결과에 48px 이상의 포스터 수치를 되살리지 않는다.
- 숫자는 가능한 tabular-nums. `~12초`의 추정 기호를 숨기거나 색 대비를 낮추지 않는다. `2.9km/h`는 설정 하위의 명시적 직접값일 때만 일반 숫자로 보여준다.
- 기본 간격 4/8/12/16/24/32px. 화면 좌우 16px, 작은 화면 14–16px. 구분은 여백→정렬→행 구분선 순서로 해결한다.
- 입력·주 버튼 radius 10–12px, 작은 지도 제어면 radius 12px 또는 원. 모든 행을 pill/card로 만들지 않는다. 깊은 그림자·빛 번짐·그라데이션은 쓰지 않는다.
- 실제 터치 영역 최소 44×44px, 주 버튼 높이 최소 48px. 아이콘 20–24px가 작아 보여도 터치 영역은 줄이지 않는다.

## 4. 앱 셸과 스크롤

앱은 `100dvh`와 safe-area를 고려한다. 모바일 브라우저 주소창이 접혀 높이가 바뀌어도 하단 행동이 가려지지 않아야 한다. 외부 페이지 전체와 내부 시트를 동시에 무의미하게 스크롤시키지 않는다.

- 상단 툴바/하단 행동 바는 앱 셸의 고정 영역, 지도는 남은 공간, 긴 내용은 `.scroll-body` 같은 명시적 내부 영역에서 스크롤한다.
- **스크롤바는 보이지 않게 하되 스크롤은 가능해야 한다.** `overflow:hidden`으로 설문 선택지·설정 마지막 행을 잘라내지 않는다. 터치·휠·키보드 PageDown/방향키 이동을 확인한다.
- 푸터가 겹치는 레이아웃은 본문에 푸터 높이+safe-area 이상의 아래 여백을 둔다. 가능하면 grid/flex의 독립 푸터를 쓴다.
- 설문/설정은 헤더–스크롤 본문–푸터 3영역이다. 설정이 길어지면 폰트나 터치 크기를 줄이지 않고 본문만 스크롤한다.
- 드래그 핸들은 보조 표현이다. 드래그를 못 해도 모든 기능을 버튼·접기/펼치기로 사용할 수 있어야 한다. ‘올려서 비교’ 같은 조작 설명을 추가하지 않는다.

## 6. 화면별 치수 기준

아래는 390×844의 시작점이다. 브라우저 safe-area·글 크기·내용 길이에 따라 조정하며 고정 픽셀을 맞추려고 자르지 않는다.

| 화면 | 배치 목표 |
|---|---|
| 설문 | 상단 64px, 진행 40px, 질문/설명 약 120px, 선택 행 묶음, 하단 80px. 다음/건너뛰기 항상 접근 가능 |
| 홈 | 상단 브랜드/검색/출발 약 144px. 지도 45–55%, 아래 측정 상태·최근 목적지 최대 2행, 행동 바 72–88px |
| 결과 | 출도착 약 96px, 지도 중심 약 52–62%, 경로 2행 약 120–144px, 부족 정보 36–44px, 행동 바 72–88px |
| 설정 | 상단 64px, auto·학습 상태·직접 정하기·설문 수정·요약 저장·초기화의 단일 행 목록, 하단 적용 80px |

결과의 학습/계산 기준·여유 열 라벨이 추가되면 지도 비중을 조금 줄일 수 있다. 시안의 지도 약 65%라는 인상을 유지하되 정보를 압축하려고 읽기 크기를 줄이지 않는다. 값이 긴 경우 여유 열만 다음 줄로 이동할 수 있다.

## 7. 반응형·접근성

- **360×640:** 상단 툴바+CTA 우선 유지, 지도는 가용 높이를 사용하고 상세/설정은 내부 스크롤. 두 경로 행과 정보 부족 상태가 CTA를 덮지 않는다. 설문의 4개 답과 건너뛰기를 키보드/터치로 모두 도달한다.
- **390×844:** 승인 시안의 기준. 단일 화면에 핵심 비교/CTA가 들어오고 지도는 출도착/두 경로를 가리지 않는 padding으로 fitBounds한다.
- **768×1024 및 가로:** 휴대전화 그림을 중앙에 축소해 넣지 않는다. 지도는 넓게, 제어 패널은 읽기 좋은 폭(약 360–420px)의 좌측/우측 column 또는 overlay로 배치할 수 있다. 설정 본문은 max-width 560px 안팎. 작은 breakpoint 구현도 768에서 기능이 온전하면 허용하지만 데스크톱 장식 프레임은 넣지 않는다.
- 200% 글 확대/긴 장소명에서 버튼을 밀어내거나 가로 스크롤을 만들지 않는다. 장비 선택 행·설정 행은 높이가 늘 수 있다.
- 각 screen은 heading을 갖고 비활성 screen은 `hidden` 처리해 tab 순서에서 제외한다. 새 화면의 heading에 초점을 옮기고 뒤로가기 시 진입 버튼으로 복귀한다.
- 라디오/체크박스/토글을 시각 전용 div로 만들지 않는다. 아이콘 버튼은 `aria-label`, 속도 range는 label·단위·현재값이 필요하다. focus-visible은 2px 이상 노랑 외곽선과 간격으로 표시한다.
- 위치/학습 상태는 적절한 `role=status`로 알리되 GPS 갱신마다 초 단위로 화면낭독을 반복하지 않는다. 동작 중 숨겨진 버튼에 포커스를 남기지 않는다.
- 미확인/추정은 색 외 문구·점선·`~`로 구분한다. reduced-motion에서는 장식 애니메이션을 끈다.

## 8. 시각 완료 조건

모든 조건을 실제 브라우저에서 확인하고 뷰포트·상태·한계를 검증 보고서에 남긴다. 이미지 승인만으로 통과라고 하지 않는다.

1. 기본 화면에 수동 속도 슬라이더·이전 기록 탭·대형 홍보 제목·시간 막대가 없다.
2. 네 승인 시안의 정보 위계/무광 색/지도 중심 배치가 이어지고 실제 지리 데이터는 별도로 유지된다.
3. 360/390/768에서 가로 넘침 0, 주 행동 가림 0, 보이지 않는 스크롤바와 실제 스크롤 모두 동작한다.
4. 학습 전·부족·수동·충분·저장 실패·위치 실패·지도 실패·신호 미확인 상태가 겹침 없이 보인다.
5. 44px 터치, 48px 주 행동, 포커스, 대비, 키보드·글 확대를 확인한다. 지도 주석/법정 attribution은 숨기지 않는다.
6. 생성 시안의 `~12초`, `18분`, 가짜 현재 위치를 실제 응답으로 하드코딩하지 않는다.
