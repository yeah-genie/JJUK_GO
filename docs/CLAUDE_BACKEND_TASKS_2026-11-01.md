# UI 작업 없이 이어갈 데이터·엔진 작업

사용자 요청: GitHub 최신 변경을 보존해 Vercel에 반영하고, UI 이외에 이어서 할 일을 정한다. 제품 기준은 **조금 더 걸리더라도 내 걸음으로 편한 길**이다. 이 문서는 작업 지시안이며 완료 보고가 아니다.

## 시작 방법과 작업 경계

- 최신 `origin/ccr-94bac9df-i81579`에서 시작한다. push 전에 다시 fetch하고 다른 작업자의 커밋을 덮어쓰지 않는다.
- `docs/prototype/reference-ui/`의 레이아웃·CSS·로고·정보 순서는 변경하지 않는다. 백엔드 변경에 UI 연결이 필요하면 데이터 계약과 예시 JSON을 문서로 제안한다.
- 신호 신뢰 기준을 낮추거나, 지속시간만 있는 기록에서 현재 신호 위상을 만들어 내지 않는다. 기록 재생은 임의 시작점의 시연이며 현재 신호가 아니다.
- 새 데이터는 저장소의 기존 자료를 먼저 확인한다. 출처·라이선스·갱신일·결측률·공간 연결 정확도를 함께 기록한다. 비밀 키와 원시 GPS는 커밋하지 않는다.

## 1순위: 신호 정보가 실제로 얼마나 유효한지 검증

결과물: `reports/data/SIGNAL_COVERAGE.md`와 재실행 가능한 집계 스크립트.

1. 위치만 있음 / 지속시간만 있음 / 해당 요일·시간의 패턴 있음 / 기존 교차 날짜 신뢰 기준 통과를 구분한다.
2. 종로·성북·강남·마포 대표 지점과 요일·시간별로 분모·개수·자료 날짜를 제시한다. 교차로 ID 수를 검증된 횡단보도 수라고 쓰지 않는다.
3. 제외 이유를 집계한다: 방향 미연결, 시간대 없음, 표본 부족, 날짜간 불일치, 횡단 길이 미확인.
4. 실제 현장 대조가 필요한 횡단 10곳의 검증표를 만든다. 지도 방향·횡단 길이·초록/점멸 정의를 별도 열로 둔다.

완료 기준: 같은 자료와 기준으로 재실행하면 수치가 같고, 커버리지 수치를 개선하려고 신뢰 기준을 변경하지 않는다.

## 2순위: 편한 길이 정말 덜 불편한지 회귀 시험

결과물: `reports/experiments/COMFORT_ROUTE_REGRESSION.md`, 고정 출발·도착 쌍과 자동 검사.

1. 평지·산지·계단·길 단절·한강 주변·탐색 범위 끝 등 최소 30쌍을 고정한다.
2. 느린/기본/빠른 걸음과 추가 시간 예산에 대해 빠른 길·편한 길의 거리, 보행 시간, 확인된 계단, 급경사 거리, 상승 높이, 신호 수를 원시값으로 비교한다.
3. 기존 추가 시간·악화 금지·중복 경로 제외 기준을 지키는지 확인한다. 유효 대안이 없으면 없는 것으로 처리한다.
4. 경사 미확인을 0으로 바꾸지 않는다. 반대로 압축으로 생략된 0값 `e.f`를 결측으로 오인하지 않는다.
5. 출발 지연과 앞선 신호 대기를 반영한 도착 시각 계산이 경로 카드와 일치하는지 시험한다.

완료 기준: 사용자에게 노출되는 수치와 엔진 결과의 일치, 경로 단절·예산 초과 회귀 방지. UI 모양은 바꾸지 않는다.

## 3순위: 수집 파이프라인 점검

결과물: `reports/data/COLLECTION_HEALTH.md`.

- 최근 24시간 Actions 실행 간격, 성공 여부, 마지막 정상 원본 시각, 마지막 앱 반영 시각을 각각 조사한다. 스케줄 선언만 보고 5분마다 수집됐다고 말하지 않는다.
- 원본 다운로드 실패·잘린 ZIP·부분 자료가 기존 정상 산출물을 덮지 않는지 시험한다.
- 실패 원인과 복구 방법을 기록한다. 새 유료 서비스·API 활성화는 제안부터 한다.
- 실시간 API는 관측/예외 확인 용도이며 승인·수집 상태를 사실대로 적는다.

## 다음 후보: 접근성 자료 연결 가능성 검증

기존 그래프·횡단보도·지면고도 자료와 서울 보행 네트워크/통행 불편/승강기 공개 자료를 대조한다. 우선 1개 지역에서 출입구·경사로·엘리베이터의 연결 정확도와 결측을 평가하는 보고서를 만든다. 위치가 가까운 시설을 통행 가능한 연결이라고 단정하지 않는다. 시설 운영 상태를 모르면 모름으로 둔다.
