## 질문 (영향이 큰 순서)

### Q1. 신호 방향 코드 `nt/et/st/wt`는 무슨 뜻인가? (영향 가장 큼)
- 배경: `scripts/export_history_plans.py`는 `nt/et/st/wt`를 `n/e/s/w`로 그대로 옮기고, 앱은 횡단보도 선의 방향(`sidewalks.compass`: 건너는 큰길 다리가 향한 방위)과 짝짓는다. 두 가정이 모두 아는 횡단 72곳에서 초록/빨강이 69%만 일치했고, 경로 25개 중 13개는 멈춤 횟수가 달라졌다(Winston §2-1 (3)). **방향 코드가 '걷는 방향'인지 '횡단하는 곳의 위치'인지 모르는 것이 원인일 수 있다.**
- 물어볼 것: T Data 10382 파일 명세 또는 MAP API(10121)의 방향 필드 정의를 확인했나? 정의 문구와 출처 링크, 그리고 `*_PDSG`(보행 신호) 상태값 목록과 각 값의 뜻.
- 있으면 좋은 것: 이 코드를 현장 횡단보도와 맞춰 본 적이 있는가.

### Q2. `permissive-Movement-Allowed`는 녹색 점멸인가? 점멸 중 건너기 시작해도 되는가?
- 배경: 우리가 쓰는 "초록 길이"는 점등+점멸의 합이다. 점멸 중에는 건너기 시작하면 안 된다는 규칙이 있다면 "건너기 시작할 수 있는 시간"은 훨씬 짧다. 지금의 `MIN_GREEN=8`(초록이 8초 이상 남아 있어야 건넘)도 근거가 없다.
- 물어볼 것: 상태값 의미 확정(공식 문서 링크), 그리고 보행 신호 시간 산정 기준 속도(논문에서는 일반 1.0m/s, 교통약자 0.8m/s로 언급되나 법령 원문·경찰청 매뉴얼은 확인 못 했다)의 공식 근거.

### Q3. 다른 13일 데이터로 요일·날짜 안정성을 시험해 줄 수 있는가?
- 배경: 앱이 쓰는 08~10시 패턴의 30%가 토·일 날짜에서 맞춘 것이다. Claude 세션은 하루(10/27 화)만 시험할 수 있었다. 평일 패턴→화요일 적중 98.5%, 주말 패턴→화요일 79.3%("항상 빨강" 기준선 77.6%). Release 자산은 Claude 세션에서 403이었다.
- 요청: 14일 CSV.GZ로 leave-one-day-out(평일끼리, 주말끼리, 교차, 날짜 거리별)을 돌려 주세요. 합격 기준 제안: 평일→평일 적중 95% 이상인 시간대·방향이 90% 이상. 공휴일이 있었는지도 알려 주세요. 방법은 `docs/experiments/winston_2026-10-29/xday.py`(임시 경로 하드코딩, 방법 참고용).
- 부가: 09시 관측이 10/27에 0건이었던 이유(수집 구멍인지 원본 구멍인지). 시간대 파일을 하루가 아니라 여러 날짜의 합으로 만든 이유와 영향.

### Q4. 서울시 공공데이터에서 횡단보도 길이를 받을 수 있는가?
- 배경: [OA-21209 대로변 횡단보도 위치정보](https://data.seoul.go.kr/dataList/OA-21209/S/1/datasetView.do?tab=A)는 설명에 "위치와 길이"가 있다(공공누리 1유형, Open API, 미리보기 1,000건). [OA-15554 교통안전시설물 횡단보도 정보](https://data.seoul.go.kr/dataList/OA-15554/S/1/datasetView.do)는 위치·부착대 zip(20MB)과 테이블 정의서(hwpx). Claude 세션은 키가 없고 외부 호스트가 막혀 실제 데이터를 받지 못했다.
- 물어볼 것: ① Codex 쪽에 서울 열린데이터광장 Open API 인증키가 있는가(있는지 여부만) ② 있다면 OA-21209 컬럼 목록·건수·좌표 범위(서울 전체인지 대로변만인지)·길이 단위를 확인해 주세요 ③ OA-15554 정의서에 길이 컬럼이 있는가.
- 현재 앱의 길이는 차선 수 환산이고 25,751개 중 92%가 5개 값 중 하나다(Winston §2-2).

### Q5. '출입구 연결 35m' 값은 어디서 나왔는가?
- 배경: Codex 브랜치가 추가한 규칙이다. 지도에서 고른 점이 걸을 수 있는 길에서 35m 넘게 떨어져 있으면 "출입구 가까이에서 골라 주세요"로 멈춘다. 장소 1,452곳 표본에서 13%(학교 63%, 쇼핑 30%)가 35m를 넘는다. 사용자가 "무슨 말인지 모르겠다"고 했다.
- 물어볼 것: 35m의 근거(측정? 임의?)와, 이 규칙 때문에 막힌 실제 사례. Claude 쪽은 35m 이하 자동, 100m까지는 거리를 보여 주고 확인, 그 밖은 거절하는 3단계를 제안했다(Winston §5). 반대할 이유가 있는가.

## Claude가 이미 확인한 것 (중복해서 확인하지 않아도 되는 것)

- 신호 횡단 25,751개 중 08시 패턴과 방향까지 맞는 곳은 36%(같은 방위 가정)~41%(직각 가정) (Winston §6 T8).
- 평일/주말 패턴이 다르면 '모름' 처리하는 안(코드 약 5줄)은 Claude가 앱에 넣을 예정이다.
- 횡단 여유는 "정적 여유 = 초록 길이 − 길이/내 속도"를 머리 숫자로 쓴다. 15.8m 횡단에서 `MIN_GREEN=8`이 '대기 없음'으로 센 도착 중 실제로 다 못 건너는 비율은 0.8m/s 50%, 1.0m/s 34%, 1.2m/s 23%(도착이 초록 안에서 균일하다는 가정).
