# 지하철·버스 추가 계획 (2026-11-01, 제안)

사용자 요청: "그리고 지하철 버스 정보도 추가할건데, 네이버 지도 참고해서 해봐."

이 문서는 제안이다. 키가 연결되기 전에는 실제 데이터를 보여 주지 않는다(가짜 도착 시간 금지).

## 1. 네이버 지도에서 가져올 흐름 (일반적으로 알려진 기능 기준)
- **길찾기 위 탭:** 대중교통 / 도보. 자동차·자전거 탭은 만들지 않는다(쭉고 범위 밖).
- **대중교통 경로 목록:** 경로마다 아래를 보여 준다.
  - 총 시간, 도착 시각, 요금, 환승 횟수, 걷는 시간
  - 노선 색 막대(도보 → 2호선 → 도보 → 버스 …)
  - 첫 탈것의 실시간 도착("3분 후 · 2정거장 전")
- **경로 상세:** 승차역·정류장, 몇 정거장, 하차, 환승 걷기를 순서대로 보여 준다.
- **역·정류장 누르기:** 실시간 도착 목록(지하철 상·하행, 버스 노선별 첫째·둘째 도착).
- **지도:** 주변 지하철역·버스정류장 아이콘.

## 2. 쭉고만 더하는 것 (컨셉 유지: 서두르지 않아도 되는 이동)
- **걷는 구간:** 출발→정류장, 환승, 하차→목적지 같은 걷는 구간은 쭉고 보행 엔진으로 계산한다. 덜 부담스러운 길과 예상 신호 대기를 쓴다.
- **"이번 차 / 다음 차" 판단:**
  - 내 걸음 + 신호 대기 예상으로 정류장 도착 시각을 계산한다.
  - 실시간 도착과 비교해 "이번 버스는 빠듯해요(예상) · 다음 버스 8분 후"처럼 알려 준다.
  - **뛰라고 하지 않는다.** 빠듯하면 다음 차를 기준으로 안내한다.
- **계단·환승 부담:** 경로를 비교할 때 환승 횟수와 걷는 시간을 먼저 보여 준다. 계단·엘리베이터는 자료 검증 전이라 쓰지 않는다(모름).

## 3. 필요한 외부 API (사용자가 발급해야 함)
| 용도 | 후보 | 키 이름(Vercel 환경변수) | 확인할 것 |
|---|---|---|---|
| 대중교통 길찾기, 주변 역·정류장 | ODsay LAB API(lab.odsay.com, 대중교통 길찾기·반경 내 POI 제공) | `ODSAY_API_KEY` | 무료 한도·요금(공식 페이지에서 확인 못 함), 웹 키는 허용 도메인 등록 필요(jjukgo.vercel.app) |
| 지하철 실시간 도착 | 서울 열린데이터광장 '실시간 지하철 도착정보' | `SEOUL_OPENAPI_KEY` | 일일 호출 한도 |
| 버스 실시간 도착 | 공공데이터포털 '서울특별시 버스도착정보조회'(서울 버스정보시스템) | `DATA_GO_KR_KEY` | 활용 신청 승인, 일일 한도 |

키는 저장소에 넣지 않고 Vercel 환경변수에만 둔다. 브라우저는 우리 서버 함수(`/api/transit-*`)만 부른다.

## 4. 만드는 순서
1. 서버 함수:
   - `api/transit-route.js`: 출발·도착 좌표 → ODsay 길찾기 → 필요한 칸만 정리해서 돌려준다.
   - `api/transit-arrival.js`: 역 이름·정류장 번호 → 지하철·버스 실시간 도착.
   - 공통: 키 없으면 `{enabled:false}`. 응답 캐시는 짧게(도착 20초, 경로 5분). 키는 오류 메시지에도 노출하지 않는다.
2. 화면:
   - 경로 화면 위 [대중교통 | 도보] 탭(키가 있을 때만 대중교통 탭이 보인다)
   - 대중교통 경로 카드(노선 색 막대), 경로 상세, 역·정류장 실시간 도착
3. 쭉고 연결: 걷는 구간을 쭉고 엔진으로 다시 계산하고 신호 대기를 넣는다. "이번 차 / 다음 차" 판단도 붙인다.
4. 시험: 가짜 응답으로 화면·계산 시험(`check_transit.cjs`). 키 연결 뒤 실제 응답 형식을 확인하고 고친다.

## 5. 정직 규칙
- 실시간 도착은 제공기관 값 그대로 쓰고 "실시간"이라고 표시한다. 신호는 계속 "예상"이다.
- 탑승을 보장하지 않는다("탈 수 있어요" 대신 "여유 약 2분(예상)").
- 엘리베이터·계단 정보는 검증 전에 쓰지 않는다.
