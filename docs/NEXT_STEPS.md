## 1. 공개 앱 배포 확인 (가장 먼저)
- **왜:** 2026-10-29에 Vercel 하루 배포 한도(100회)에 걸려 "빠른 길 vs 쭉고 길" 화면이 공개 앱에 반영되지 않았다. 원인은 수집 데이터(`data` 브랜치)가 5분마다 push될 때마다 생긴 미리보기 배포로 추정한다.
- **할 일**
  1. https://jjukgo.vercel.app 을 `?v=시각`을 붙여 열어서 새 화면(`route-metrics`, "이 길로 걷기")이 반영됐는지 확인한다.
  2. 반영이 안 됐으면 작은 문서 변경을 커밋·push해서 배포를 다시 시작한다(빈 커밋은 쓰지 않는다).
  3. 반영되면 대표 링크 2개로 실제 기기 폭에서 확인한다.
     - 신촌역→홍대입구역: `?from=37.5551,126.9368&to=37.5571,126.9245&fn=신촌역&tn=홍대입구역`
     - 혜화역→낙산공원: `?from=37.5822,127.0018&to=37.5806,127.0074&fn=혜화역&tn=낙산공원`
- **사용자에게 확인할 것:** Vercel의 Deployments 목록에 `data` 브랜치 배포가 더 이상 생기지 않는지 봐 달라고 한다. 수집 커밋에 `[skip ci] [vercel skip]`을 붙였지만 효과는 아직 확인하지 못했다. 계속 생기면 Settings → Git → Ignored Build Step에 `[ "$VERCEL_GIT_COMMIT_REF" = "data" ] && exit 0 || exit 1`을 넣도록 안내한다.

## 2. 신호 방향 검증 마무리 — 완료(2026-10-29 밤)
- 결과: 보행 코드는 같은 축 차량 직진과만 동시에 초록(17건 중 16건, 직각 축 0%). et=북쪽, st=동쪽, wt=남쪽, nt=서쪽 다리. 신호 패턴 파일·내보내기 스크립트 고침, 직진 수집 설정 되돌림. 남은 것: 숫자 개방 여부를 사용자에게 묻기.

- **왜:** 보행신호 `nt/et/st/wt`가 어느 횡단보도인지("시계방향 한 칸" 가설, T자 교차로 69곳에서 64% 일치)를 차량 직진 신호와 맞춰 확정하려고 2026-10-29 13:53 UTC부터 직진(St) 신호를 함께 모으고 있다.
- **할 일**
  1. `origin/data`의 `segments/`에서 `movement=St` 행을 읽는다(교차로 10곳).
  2. 같은 교차로에서 보행 초록과 동시에 켜지는 차량 직진 방향을 센다. 보행자는 나란히 가는 직진 차량과 같이 건넌다는 규칙으로, 보행 코드가 어느 도로를 건너는지 판정한다.
  3. 결과를 `reports/team-2026-10-29/18_서울시_신호_방향_공식설명.md`에 이어 쓴다. 판정이 서면 사용자에게 숫자 개방 여부(A 추정 표시로 열기 / B 계속 닫기)를 묻는다.
  4. 검증이 끝나면 `collect.yml`의 `JJUK_MOVEMENTS`, `JJUK_CRAWL_EVERY` 두 줄을 지워 원래 수집으로 되돌린다.
- **기한:** 옛 실시간 API만 2026-11-15에 끝난다. 수집기는 새 실시간 API(10381)를 먼저 쓰도록 바꿨다(2026-10-30).

## 신호 대기 기능(2026-10-30 추가)
- 앱은 "예상 신호 대기"만 비교한다. 건널 수 있는지는 판단하지 않는다(현장 검증 없음, 점멸 의미 미확정). 문구에 "건널 수/건너도/한 번에/안전/여유"를 쓰지 않는다(시험이 막는다).
- 신뢰 조건(app.js `TRUST`): 방향 매칭, 관측 900초·검증 300표본, 같은 요일 종류 다른 날 1일 이상 일치율 0.95(최솟값 0.9), 주기 정수, 검증 일치율 0.95·불순도 0.02, 오늘과 같은 요일 종류. 하나라도 아니면 "정보 없음".
- 대기 정의: 도착 시각에 '고정 초록(protected)'이 아니면 다음 고정 초록 시작까지. permissive(초록 점멸로 추정, 미확정)는 빨강과 같이 센다.
- 기록 늘리기: `.github/workflows/history.yml`(수동 실행/매일 04:20 KST)이 새 날짜를 가져와 전체 패턴을 다시 만든다. 하루치 파일 서비스(10382)는 11/15 뒤에도 이어진다(끝나는 건 옛 실시간 API). 하루치 파일이 없는 날은 실시간 수집으로 같은 형식을 채운다(`docs/discussions/2026-10-30-realtime-api-switch.md`). 끝나면 앱 확인 비율(QA 16곳 기준 8%)이 얼마나 올랐는지 `scripts/qa_routes.cjs`로 잰다.
- 확인 비율이 낮은 이유(QA 16곳, 53개 신호): 골목 교차로 신호 노드는 어느 다리인지 몰라 정보 없음(51%), 해당 시간대 패턴 없음(34%). 기록이 쌓이면 뒤쪽이 줄어든다.
